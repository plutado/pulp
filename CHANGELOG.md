# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **A camera take begins the moment Record is pressed.** It used to wait for Pulp to open the take's file first, which lost the take's first moments, and a Stop pressed within that half second on a slow machine dropped the recording with nothing said. Seen on Windows CI as a silent take that was never saved. Escape on the camera preview now turns the camera off at the key.

- **A voice recording appears in Recordings only once it is whole.** The take was written straight into the folder, and on Windows a file written in place is listed before its bytes are, so the library's watcher (and the end-to-end test, on Windows CI) could read a WAV whose header was not there yet. It is written to a hidden partial file and renamed into place, as a camera take already was.

- **The start screen's dark visual references hold on CI's Mac.** They failed there every run, the captures showing most gallery pictures as empty wells and a scrollbar across the gallery — neither on the Mac the references were made on, and both invisible to the hash on the light palette. A card's picture is the decoded image element itself now, not the same URL set again as a CSS background: the strip protocol answers no-store, so the background started a second fetch after the card was already marked pictured, and a busy machine's screenshot caught the well still empty. And the reference capture hides the gallery's scrollbar while it works, since what a scrollbar looks like is the machine's, not the screen's: a Mac without a trackpad draws a classic bar that takes room and shines across the dark palette. The references did not move — both fixes draw what the reference Mac already drew. Details in docs/platform-notes.md.

- **Making the sample-media folder takes about half as long**, and renders are faster again, with every frame still captured only after a frame made since the draw has been presented. The folder's clips used to be encoded frame by frame to PNG only for ffmpeg to decode each one again; they now go to ffmpeg as the raw pixels the capture produces, streamed into it while the next frame draws. And a frame no longer waits two animation frames in the page before it is captured, a wait the presented-frame check had made redundant. A full folder takes about three minutes on a Mac where it took six (and four before the check), which brings the macOS CI job's whole-folder test back well under its limit; a 1080p render runs at about 39 frames/s, up from 32.

- **A render can no longer write a frame from before its draw.** On a busy machine a captured frame could hold the previous frame's picture — seen on macOS CI as a half-speed render whose frames did not line up — because the capture waited for signs that the draw had reached the surface and none of them proved it. Each frame is now captured only after a frame made since the draw has been presented, which orders the capture by the frame itself rather than by how long anything took: with every other wait taken out, a test template that paints its own frame number was captured a frame behind 37 times in 5,400 frames before, and 0 times in 7,200 after. It applies to renders, posters and hover strips, stills, caption styles and the visual references. It costs speed — a 1080p lower third renders at about 32 frames/s where it rendered at about 52 — since the check cannot be made smaller on an offscreen window. Two test races are fixed with it, without raising a timeout or a tolerance: the stage tests now wait for the layer overlay to hold the latest frame asked for rather than any report of the same frame number, and the start screen says when everything it shows has arrived and marks a picture only once it is on screen, so its visual references capture one screen every time. Its second accepted reference is gone. Details in docs/platform-notes.md.

- **The stage's corner is four buttons of one size**: the background, the safe areas, pop out and theater. The checkerboard, black, white, gray and custom-color swatches that ran along it are one background button now, which wears the choice that is on — the board drawn small, or the color — and opens a small picker of the five; a choice, Escape or a press anywhere else closes it. The right-click menu on the stage lines **Theater** up with the items around it: a menu with anything that can be ticked keeps the tick's gutter on every row, where Theater's label had been pushed to the far edge. And the **start screen** sits in the middle of the window, top to bottom, instead of against its top edge — still starting at the top, with nothing cut off, on a window too short for it.

- **The start screen fits a short window on every platform.** Learn sat 15 to 24 px below the bottom of the window on a smaller screen, and further down with every recent project: Continue's cards wrapped into as many rows as there were recents (up to ten), and the screen needed 820 px on a first run where the window may be as short as 600. Continue is one row now that scrolls sideways, like the gallery; under 880 px each heading shares its line with its description, the checklist's three steps sit side by side and the gallery's tiles are a little smaller; and the screen sets its own line height, since Segoe UI's own made the same screen 20 px taller on Windows than on macOS. An example's description shows three lines on its tile and the whole of it on hover. The end-to-end test measures both arrangements at seven sizes from 1920 × 1080 to 960 × 600 rather than at whatever size the machine's screen allows, and the start screen's visual references are captured at a set 1280 × 788 and one pixel per point, with the forced first run's checklist drawn from fixed facts and the capture waiting for the gallery's pictures, so they hold on any Mac.

- **US English throughout.** Labels, notes, template names and descriptions, the docs, the changelog, the roadmap and the comments all read in US English now — color, center, gray, license, behavior, canceled. Internal values keep their spelling so saved work and generated files keep working: the `cancelled` render status, the `cancelled` result fields, the `carbon-fibre` and `paper-fibre` template ids, the `programme`, `fibre` and `centre` parameter ids and the `centre` option value, and two sample-media file names. They are listed, with the reasons, in `docs/spelling.md`.

- **A render the screen's size, or larger, renders on Linux.** On X11 a window that matches the desktop's size is shrunk by a pixel, so a 1080p render on a 1080p desktop was captured at 1919 × 1079 and refused, and a 4K render could not happen on an ordinary screen at all. A frame that does not fit the screen is now captured from a smaller window at a higher device scale, with the page told its real size, and the result is the same bitmap byte for byte as a render on a large screen — checked on a 1920 × 1080 virtual screen in the end-to-end tests. The one size still refused is an odd one that shares no whole factor with anything, and the message now names the screen that is in the way.

- A saved **"Hold, seconds" is carried into a length** instead of being lost. Eleven bundled templates — the citation callout, the city lights and civic openers, the donation, fitness and lap counters, the handle and profile cards, the poll strip, the hairline lower third and the kicker title — lost that parameter when they declared their parts, since the length is the control now. Work saved before then still carried a value for it, and until now it was dropped: the render fell back on the template's own hold and the value was reported as an unknown parameter. It is translated now — the declared entrance and exit with the saved hold between them, held inside the length's own limits — for every kind of saved work: a preset, a collection item, a `.pulpcollection`, a `.pulp` project, a CSV column (which used to be ignored outright) and `--param` on the command line. A render says what it did. A length saved alongside wins, since a length someone chose outranks one worked out from a parameter that no longer exists, and nothing outside those eleven is touched: `inOut` is a live parameter on thirty other templates.

- **Layouts made for vertical video are complete** (milestone 65). Four **frame layouts** arrange the picture itself for a tall frame, with no black bars. **Frame Wide Clip** sets a wide clip sharp across the middle with the same clip blurred behind it, a title above and room for captions below. **Frame Stacked** puts two clips top and bottom. **Frame Corner Face** puts a face in the top left over a full-frame clip, as a video layer on the picture track, so it is moved, sized, cropped and timed like any clip. **Frame Caption Card** is a full-frame clip with a card. Eight **overlays for short video** keep clear of the apps' controls: a progress bar along the top that fills over the whole video, a part tag, a list counter, chat bubbles that arrive one by one, a reply-to-a-comment card, a poll, a follow prompt for the end, and a place or product tag. All twenty-two templates made for vertical now have a **Made for vertical** node under Quick access. Clicking a template that draws only 9:16 never reorders the results under it, and a chosen sort or typed words keep their order. - **Layouts made for vertical video begin** (milestone 65): ten templates designed for a tall frame first, rather than drawn wide and fitted to one, tagged **Made for vertical**. Six **hook titles** are headlines for the first second of a short video, set large in the top third: **Hook Bold** (two heavy lines over a shade), **Hook Question** (a card sized to the question), **Hook Keyword** (a marker sweeps behind a word you name), **Hook Bar** (a meme-style bar across the top), **Hook List** (a big number in a ring that draws itself) and **Hook Quote** (an oversized quotation mark and who said it). A new command, **`pulp safe-box`**, holds every template made for vertical to both. It draws each one at 9:16 where it has settled, draws it again with every word changed, and takes the words to be wherever the two pictures differ, which works on a canvas with no page structure to ask. The end-to-end suite runs it on every platform. On its first run it caught a caption that popped a long word into the controls column for a tenth of a second. A fresh set of captions still starts on a style drawn for every shape, so a wide project never defaults to one placed for a tall frame alone. Frame layouts, overlays for short video, and finding these first when the work is tall are still to come.

- **Record from a camera with one click** (milestone 64). A camera button beside the microphone — or **File → Record Video** — opens a live preview from the system's camera, with its sound; **Record** starts the take with the elapsed time over the picture, and Record again (reading Stop), Escape or Close ends it and keeps it. The take lands in the **Recordings** folder beside the voices, named by date and time, and joins the library selected, with a poster and hover scrub like any clip. The window records WebM, the one format Chromium's recorder writes on every platform, at a variable frame rate that editors drift on, so it is converted with FFmpeg to **H.264 and AAC in an MP4 at the camera's own size and a constant frame rate at its own** — libx264 where FFmpeg has it, VideoToolbox, Media Foundation, NVIDIA or AMD where it does not — and where nothing can convert it the WebM is kept and the tray says why. The take reaches the main process a second at a time, into a staging file outside the library, so a long take is never held in memory and a camera unplugged mid-take keeps what it recorded. The preview's **Camera** and **Sound** menus choose the camera and the microphone, or **No sound**, and remember them; a camera facing you is mirrored in the preview and never in the file. Permission is asked plainly: the camera's own prompt and usage description, then the microphone's when sound is on, with the way to the settings after a refusal. A voice and a camera's take never hold the microphone at once. Unit tests convert a real variable-rate WebM wherever FFmpeg is installed; the end-to-end suite records from Chromium's fake camera and finds a playable clip of the right size, rate and length in the library.

- **Light and dark appearance** (milestone 62). **Settings → Appearance** and **View → Appearance** offer System — the default, which follows the operating system and changes when it does — Light and Dark, kept with the other settings. A change redraws every window at once with no restart: the main window, the popped-out stage, Settings and the other dialogs, and the start screen, which now comes up in the chosen appearance rather than the system's alone. Every color in the window's styles is a token now (sixty-odd were written in directly), with a light palette for each that holds text, icons, focus rings and the accent to WCAG AA, checked by a test that also fails on any color written outside the tokens. The stage's checkerboard and the backdrops behind a transparent item's card follow the appearance, lighter in Light; what belongs to the work looks the same in either: a chosen black, white, gray or custom stage background, the safe areas and whatever a template draws. A template's preview and its captions are shown in frames that carry the template page's own color scheme, so a transparent graphic is never set on an opaque backdrop the window's palette would otherwise paint behind it. **No flash at launch:** the window is made hidden on the chosen palette's background and shown once its page has drawn, and the page sets the same background before its stylesheet loads, so neither appearance ever shows the other for a frame. The editor panels follow their host instead: Premiere's panel brightness picks the panel's light or dark palette, and Resolve's stays dark. End-to-end tests switch from Settings and the menu and find each window redrawn, and visual references of the main window in each appearance join the suite.

- The start screen redesigned around a clear way in (milestone 60). **New project** is the screen's one primary action, with **Open…** beside it, the four shapes as small tiles drawn in their own proportions and the platforms in one "For a platform" list — not sixteen chips. Below, sections in reading order, each with its icon and a one-line description: **Continue** (recent projects with recognizable thumbnails), **Start from an idea** (the making choices and the example projects as one gallery of real pictures — a card whose poster is not made yet wears its hover strip's first frame, made on demand, and every tile scrubs under the pointer), and **Learn**. A first run leads with the set-up checklist as one card and its progress ("2 of 3 done") and an invitation in Continue's place; once set up the checklist leaves the screen (**Help → Set-up Checklist** still shows it) and the library at a glance is one quiet line in the foot. The screen follows the system's light or dark appearance with its own palette, both held to WCAG AA by a computed test; at every window size, down to the 960 × 600 the window allows, the whole screen fits without scrolling; and its visual references — both arrangements, both themes — join the test suite.

- The visual template editor is complete (milestone 55): what is composed on the blank canvas saves as a **template folder in the open format**. **File → Save as Template…** writes `template.json` and a generated page into a folder named in the save dialog, adds it to the library, and shows it — reopened for editing, its layers editable exactly as they were on the canvas, and the file editable by hand afterwards. Everything travels: the layers with their motions, keyframes, spans, looks and **layouts per aspect** (a placement is kept per shape; **Use this layout on every shape** hands the one on screen to the shapes not laid out yet), the chosen length, and the **picked parameters as the template's real parameters**, each defaulting to the value it was picked at and driving the very layer property it was picked from. One rule guards what travels: a template never ships a library id, so a chosen picture, clip or sound stays behind — the layer saved empty, the tray saying so. A template built step by step in the UI is held, pixel for pixel across frames, to a hand-written twin.

- Motion in the template editor (milestone 55's third piece). A layer on the canvas gets its motion from the keyframes and easing and the entrances and exits the layers already had — and the canvas now has what it was missing to use them. **A block can declare the motion its layers start with**: the blank canvas fades every layer in and out over half a second, since it has no movement of its own to lend. **Motion presets** — Still, Fade in and out, Slide in from the left or right, Rise from below, Pop, Wipe on, Drift across, Pulse, Spin in — give a layer a whole motion in one choice, from a **Motion** select on its card or an **Animate** submenu on the stage's right-click menu and the Edit menu; a preset writes an entrance and an exit and, where the layer moves while it is on, keyframes with easing spread over its time on screen, and the layer is an ordinary layer afterwards, edited as before. **Record Keyframes** joins both menus as a checkbox, so milestone 51's recording is thrown from the stage.

- Parameters by picking (milestone 55's second piece). Any property on the canvas — a line's **words**, a line's or a shape's **color**, a still's **picture** — becomes a template parameter by picking it and giving it a name: **Make Words / Color / Picture a Parameter** on the stage's right-click menu and the Edit menu, or the pick button on the property's own card. The parameter lands in a **Template parameters** section at the top of the Parameters tab, named after its layer with the name ready to retype, and its control — the text field, the color field, the picture well — edits the very layer property it was picked from, so there is one value with two ways to reach it, never two values. Parameters travel with the work (projects, presets, collection cards, undo), un-picking leaves the layer's value in place, and saving the canvas as a template will carry them as its manifest parameters.

- The visual template editor begins with a blank canvas (milestone 55's first piece). **File → New Blank Canvas** (Cmd/Ctrl+Shift+N) opens a bundled template that draws nothing of its own — a transparent frame at every aspect, any length — with one open block covering the frame, for **composing a graphic from scratch**: text, pictures and clips go on it as the layers they already were, placed, sized and turned with the stage's handles and timed with each layer's own start, end, entrance and exit, and what is composed saves in a project like any other work. New with it, and on every template's layers everywhere: the **shape layer** — a rectangle, ellipse or triangle with a color, a size and a width-over-height ratio, the first layer that needs nothing chosen from a library — added from the Parameters tab, the Edit menu or the stage's right-click **Add Shape Here**, with the full look pipeline (shadow, glow, outline along its own edge, blend, wipe) and the keyframes, traveling through projects, presets, collections, CSV and `@layers` like every layer. A template may even ship shapes of its own, in the manifest and the JSON Schema.

- A Pulp panel inside the editing apps (milestone 54, begun; decision record 0025). A panel for **Premiere Pro** (a CEP extension) and one for **DaVinci Resolve Studio** (a Workflow Integration plugin) lists the running Pulp's **library and collection** without leaving the edit: one shared page in `panels/`, installed by `npm run panels:install` and documented in `docs/editor-panels.md`. The panel's search field speaks Pulp's own query syntax — it *is* Pulp's search, answered by the app — and the collection mirrors the tray, with items the library has lost marked missing rather than dropped. The connection never leaves the machine: Pulp listens on **127.0.0.1 only**, and only while **Settings → Serve the editor panel (local)** is on — off by default — with a fresh 256-bit token written to a file beside the settings that only you can read, required of every request, so a stray web page that can reach loopback but not your files is answered 401 and nothing else. Items are named by library id, and no listing carries a path.

- The panel drops into the edit (milestone 54's second item). Every row has **Bin** and a timeline button, and **drags**: the item is **rendered on request with its own output settings** — a collection item with the settings its card carries, a bare template with its type's saved output default, and **ProRes 4444 where nothing is saved, so what lands in the edit keeps its alpha** — through the same managed cache the app's own Prepare for drag fills, so a second drop of the same thing is instant; a bare media item is handed over as its own file. The row says how the render is going as a percentage, and what cannot be answered for says why. In Premiere Pro the buttons import into the insertion bin and insert at the playhead on the first unlocked video track; in Resolve they import into the media pool and append to the timeline, and dragging a rendered row is a **native drag of the file**, dropped on the timeline exactly where the pointer puts it.

- The panel goes back the other way (milestone 54's third item). **Open** on any row shows the item in Pulp — on the stage with its controls, Pulp's window brought to the front — or, for a collection item, opens that card for editing in the inspector, so a graphic can be changed in Pulp and dropped again from the panel with the change. And **Pulp's render queue is in the panel as it runs**: every job with its state and a bar for how far it has come, read by the second while anything renders — a drop prepared from the panel or a render started in Pulp alike — with **Cancel** while a job is still queued or running, and a finished render dropping into the edit like any row.

- The panels are packaged and tested, which finishes milestone 54. `npm run panels:package` writes one archive per host — `pulp-panel-premiere-<version>.zip` and `pulp-panel-resolve-<version>.zip`, each with its own `INSTALL.md`, stamped with the app's version and the same bytes for the same files — and a signed `.zxp` for Premiere wherever Adobe's ZXPSignCmd is on the machine, so the Premiere panel installs through an extension manager with no debug flag. Resolve's own `WorkflowIntegration.node` is never packaged; the install steps say where it comes from. And the panel's code is held by a **stand-in host**: the very scripts the packages carry run in a DOM over a real bridge, with Premiere's CEP surface and the Resolve plugin's preload each stood in for, so how the panel finds Pulp, what it lists, which call each button and drag ends in and with which file are all tested without either editing app installed. `docs/editor-panels.md` has the install steps from a package and from a checkout.

- All caps is a parameter on the Newsdesk set. Its eleven lettered templates — the lower third, title, opener, ident, ticker, caption, pointer, overlay, social, poll and end card — forced every word into capitals as the set's house style. Each now has an **All caps** switch, **on by default so existing work renders exactly as before**, and off keeps the words as typed. Nothing else about the set changes: the visual references match as they were.

- Music moods (milestone 16's moods). Sounds can be browsed and searched by **how they feel**, beside what they are and what they are about: a **Mood** chip joins For… and Look in the search bar — there only while the library holds moods — offering upbeat, calm, dramatic, epic, tense, playful, melancholy and mysterious with counts, and `mood:calm` is the same fence in the search field's own words. Moods come from the person's own words in two places: a folder named for one (`Music/Calm` tags what it holds, with aliases — Chill, Suspense, Uplifting…), and the file's **own metadata** — the genre, mood or comment tag ffprobe already reads in the background pass — so a library of real music tagged "Chill" browses by feel without renaming a thing. The bundled music and ambience are tagged: every music piece carries at least one mood, stems feel as their song does, and the moods are written into each generated file's genre tag, the very channel a person's own files are read by. The Info tab says an item's mood, and the semantic search embeds it.

- Media slots (milestone 22, finished). A template may now take a **moving clip** where it could only take a still: a `media` parameter declares a box, and the chosen library clip plays inside it, frame-accurately, inside the template's own animation — a plate behind a title, footage inside a frame. The clip is picked and set up with the very field a video layer's clip is: an in and an out point in frames, loop or play once, a speed, a start delay, its own volume and mute, a LUT. The host decodes exactly the window the slot plays and names the frame for every moment with the arithmetic a video layer uses, so the preview and the render agree to the frame and a slot and a layer playing the same clip show the same one; the clip's sound joins the mix, the meter and the preview as a layer's does. `state.media[id]` and `window.pulpDrawMedia` are the template's side, answering false while the slot plays nothing so the template draws a fallback. The value travels everywhere a parameter does — projects, presets, collections, JSON on the command line, a CSV cell's text form — and its id joins the render cache key. The bundled **Plate Title** is the worked example: a clip covering the frame behind a title, a flat color where none is chosen.

- Semantic search, entirely on this machine (milestone 9, decision record 0024). **Search by meaning (local)** in Settings — off by default — lets "something calm for a podcast intro" find the calm openers and the podcast end card that match none of those words. - A proper `pulp` command. What was `--render` and friends as flags on the app itself is a command with subcommands: `pulp render <template-id> --out <path>`, `pulp collection <file> --out <folder>`, `pulp sample-media <folder>`, `pulp visual-hashes <file>`, `pulp help [command]` and `pulp version`. `pulp help render` lists every option, drawn from the same table the parser reads so the two cannot drift; an unknown option, a missing value or a stray argument is named with the command it was about and where to read more; and the **exit codes mean something a script can act on**: 0 the work was done, 1 the work failed (ffmpeg refused, a template threw, an item or a row did not render), 2 the command line was wrong. - Long projects and recovery (milestone 58, finished). **A ten-minute shot previews now**, and a 30-minute cut track costs what a 30-second one did: the preview decodes ten-second tiles of a cut around the playhead rather than whole windows — which a shot over thirty seconds could never fit — and holds only the tiles it is drawing from, under a budget a test holds while scrubbing a ten-minute shot end to end. - Scale, measured and held (milestone 58, in part). - Captions from speech, as far as the words and the look (milestone 50): transcription on this machine, a captions layer and three caption styles. **Transcribe…** on the Captions card in the Parameters tab listens to whatever the project has sound in — the cut track's mix, an audio layer, a clip's own track, or all of it — and writes the captions from what was said. Nothing of your project ever leaves the machine. Decision record 0021 has the model, its size and its license; whisper.cpp itself is found on PATH, as ffmpeg is.

- The cut track finished: the edit exported for an editing app (milestone 49). **Export Edit…** on a cut's right-click menu — or `--export-edit <base>` on the command line — writes three files beside each other: the track as **FCPXML 1.10**, the spine of cuts with the clips referenced **in place** as file URLs (nothing copied), the graphics connected above the first cut, and a cross dissolve written only where both sides hold the handle material it overlaps, since an editor refuses a transition over material that is not there; the track as a **CMX3600-style EDL**, one event per cut with the source files named and every transition the format has words for (`D` for a dissolve or a dip, `W001` for a wipe); and the **graphics rendered with alpha** — the project with its track taken out, ProRes 4444 at the piece's own length — so the titles sit over the footage in the editing app exactly as they sat in Pulp. A cut also **remembers where its clip's file was**, like a collected item does: a saved project whose footage moved heals by that path the moment the moved folder is back in the library — in the window, in a headless render and in the export alike — since a library id is the hash of a path. OpenTimelineIO was left out on purpose: FCPXML and an EDL are what the finishing apps read directly, and OTIO would add a dependency to say the same timeline a second way.

- The cut track's editing is finished (milestone 49, but for the editing-app hand-off). **The project's length follows the track** now: every drop, trim, split and delete writes the length from the track's own duration, held to the template's structure, and removing the last cut hands the template its own length back. **Transitions sit on a cut** — a dissolve, a dip to any color, and any bundled wipe — chosen from the cut's right-click menu with a duration at ¼, ½, 1 or 2 s, or set by dropping a wipe from the results onto the join it should play over, and marked on the boundary. The duration is taken from both sides, half each, never more than either shot has: a dissolve cross-fades over held edge frames so the join's length stays the two cuts' lengths to the frame, a dip fades out to its color and in from it, and a wipe plays the bundled template over the join, its timeline spread across the duration — the same three in the preview and the render, from one arithmetic. **A cut's sound unlinks** for J and L cuts: a lead plays the material before the picture's in point under the previous shot, a tail runs on under the next, and Muted silences the cut with its numbers kept — Linked puts it back. And **silence removal**: Remove Silences… asks for a threshold and a minimum length, finds the quiet stretches of the track's sound with ffmpeg's own detection, **shades them on the track before anything is cut**, says how many and how long, and cuts them all in one undo step — a straddled cut splits around the quiet, keeping its sound on the first piece and its transition on the last.

- The cut track plays and renders (milestone 49). The project's shots now reach the picture and the sound, not only the lane. **In the preview** the track draws under the graphic — a canvas over the stage's background, beneath the transparent template — frame-accurate across its cuts: each cut's window is decoded once at a proxy size through the very pipeline a video layer's window takes, and the frame on screen is picked by the track's own arithmetic, so a cut boundary lands in the preview on the frame it lands on in the file; a letterboxed clip sits over the pad, exactly as the render pads it. **In the render** every preset takes the whole as one file: each cut is its own input sought to its window, brought to the output's clock and frame, joined end to end, padded on in time (a short track shows the pad rather than ending the file), trimmed to the rendered range, and the graphic composited over it — a flattening render pads with its chosen background, and a matte pass stays the graphic's own alpha, which is what an editing app wants over footage. **Each cut's sound follows it into the mix** — the preview's elements, the render's chains, the loudness meter and the leveling all hear it, gated at each boundary so a cut is a cut without the click — **with its waveform on its stretch of the track**, drawn from the library's cached peaks through the same resampling a layer's bar uses; a clip with no audio stream contributes nothing and stays plain. And **a clip dropped on the stage lands on the track** now — the shots of the project — while a drawn asset, a Lottie or a frame sequence still becomes a layer, and pictures and sounds land as they always did. The track travels as `--param @track` on the command line too. (The entry above catches the milestone up to everything but the editing-app hand-off.)

- The start of the cut track (milestone 49). A project can now hold **clips cut end to end under its layers** — deliberately one track, not an editing app's many: the shots of a short, with graphics and sound above them. Drag a clip from the results onto the strip under the scrub bar and it joins the track at the boundary nearest the hand; **Cmd/Ctrl+B splits** the cut under the playhead; **either end trims by dragging**, the edge snapping to the other cuts, the playhead and the in and out marks; **Delete ripples a cut out** and the rest close up; and a cut **moves along the track** by its body, landing at the nearest boundary. Every gesture — a drop, a split, a trim, a delete, a move — is exactly one undo step, and a split at a boundary writes none. The track is end to end by construction, so there are no gaps to manage and every edit ripples; it rides with the parameters (like the layers and the length), so projects, presets and the undo history carry it, and a project without one works exactly as before. (When this landed the track did not yet reach the preview or the render; the entry above catches it up.)

- Voice treatments (milestone 53). A talking head recorded on a laptop microphone often sounds like one: room noise, hum, uneven level, harsh esses. A **Voice** choice now sits with the volume on any layer with sound — an audio layer, or a clip's own track — offering six named treatments, each a fixed recipe of ffmpeg's own filters run locally: **Clean voice** (noise down, rumble and hum out, gently leveled, a little clarity, the esses softened), **Podcast** (a fuller spoken-word sound), **Reduce noise** (noise reduction alone), **Phone** (a telephone's narrow band), **Radio** (broadcast-style: tight level, bright presence) and **Warm** (low end lifted, highs eased) — each described in one line where it is chosen, with one **amount** for how much of it is heard, every parameter of the recipe scaled by it. The preview plays the treated sound — the main process renders it once through the very recipe the render mixes by, into a bounded cache, and the layer's element swaps to it — the transport row's meter measures the treated mix, and the treatment lands in the layer's chain before the loudness leveling, so a platform's target still holds. The choice travels with the layer into projects, presets, collections, CSV batches and `@layers` on the command line, and deliberately no further than this: no per-band curves, effect chains, reverb design or plug-in hosting — sound that needs those is finished in an audio app, which is where Pulp hands over. The sample catalog gains `noisy-voice-memo.wav`, a voice-like phrase over a hissy room left noisy on purpose, and the end-to-end test reads off the rendered files that Reduce noise really lowers its noise floor.

- Keyframes as marks on each layer's bar, finishing keyframes on layers (milestone 51). Every key is a diamond on its layer's bar under the scrub bar, at the moment it holds — on the bar's row rather than inside its body, since a key sits in the graphic's own time and can sit outside the layer's span, still holding the pose at its edge. A mark **drags in time** exactly as an end handle does (the bar's scale when the drag began sets how far a pixel goes, one undo step per gesture), the arrow keys move a focused mark a tenth of a second — a second with Shift — and Delete removes it. **Copy, paste and delete** live on the mark's own right-click menu and on Ctrl/Cmd+C and V: the copied key is its pose and easing, never its moment, and pasting writes it at the playhead on whichever layer's bar you ask — the bar's body offers the paste too while a key is held. A drag that lands on another key replaces it, exactly as writing a key there would. And the composition is now proven as one: a unit test and an end-to-end render hold a keyed layer with its own entrance, exit and span to the composed numbers — absent outside the span, part-lit inside each fade at the keyed position, whole between them — read off the same pixels the preview answers for, with a preset keeping the keys on the stack it stores.

- Keyframes on layers, with easing (milestone 51). A layer's position, scale, rotation and opacity can move over time: turn **keyframing** on for a layer (under **Animate** on its card) and dragging it on the stage, turning it or fading it writes a key at the playhead — or write one outright with **Add key at the playhead**. The value travels from a key to the next by the earlier key's easing: linear, ease in, ease out, ease in and out (CSS's own curves), hold, or a cubic bezier of the key's own. A keyed layer moves by its keys instead of where it was placed, composed around the template's own motion, and the preview and the render agree to the frame because both draw through the same arithmetic. Keys travel with the layer into projects, presets, collections and `@layers` on the command line.

- Clip clean-up for compositing (milestone 52), finished. **Key out a color…**, in a clip's Info tab under Clean up, renders a green- or blue-screen clip to an alpha clip: the dialog shows the same frame plain — a point on it picks the color — and keyed over a checkerboard as the tolerance and spill move, and the result is written beside the original as `<name> alpha.mov` (ProRes 4444, its sound kept), joining the library as an asset ready to place. A **`.cube` LUT** grades the whole render (a row in the Output tab, `--lut file.cube` on the command line), a clip rendered itself, or a video layer — where it is decoded into the layer's frames, so the preview shows the grade the render will write. **Split at its cuts** finds a long file's scenes with ffmpeg's own scene detection and stream-copies them, without re-encoding, into a `<name> scenes` folder beside it, each clip a library item of its own; a file with no cuts says so rather than splitting into one piece.

- Waveforms on the timeline, finishing sound in a project (milestone 48). Every layer with sound — an audio layer, or a video layer whose clip carries a track — shows its waveform on its bar under the scrub bar, drawn **at the project's time**: the peaks the library already caches are resampled through the same arithmetic the sound plays by, so an in point shifts the shape, a loop repeats it, a clip's speed squeezes it, the fades taper it, and a beat sits on the bar exactly where it will be heard. A muted layer still shows what it holds, since the bar is about time rather than level; with the bar already moving the sound, a cut can now be lined up with a beat or a word. Audio travels everywhere a layer does — projects, presets, collections, CSV batches, `@layers` on the command line — and a moved sound relinks exactly as far as a moved clip.

- The mix leveled to the platform's loudness target, with a meter in the transport row (milestone 52). Each platform preset now carries the −14 LUFS / −1 dBTP the platforms normalize playback to, and a render aimed at one has its mix leveled there in two passes (EBU R128): measured first, then one transparent gain over the whole mix rather than a limiter chasing it — so what is uploaded is what is heard, with no surprise gain on the platform's side. The **loudness meter** beside the transport row's volume shows what the same measurement says of the project — measured once per change to what is heard, never per frame — with the chosen platform's target as a notch on the scale and the distance to it in the tooltip; the Output tab's platform summary says the leveling beside the shape, rate and encoder it sets. A render aimed at no platform is left exactly as mixed, and a silent project shows no meter at all.

- Sound in a project: audio layers, one mix in the preview, and the mix in every render (milestone 48). There was nowhere to put music or a voice-over under a piece. **Add layer → Audio** puts one in — or drop a sound or a piece of music from the results straight onto the stage, or onto an audio layer's card to swap what it plays. It has an in and an out point **in seconds** (a sound has no frames, and you think "from eight seconds in"), **loop or play once**, a **start delay**, a **volume** and a **mute**, and a **fade in and fade out**. It draws nothing and takes no room in its block; it is a layer so that it gets a bar under the scrub bar, hiding, ordering and every route a layer travels — projects, presets, collections, CSV batches and `@layers` on the command line — and its span holds its sound, so dragging that bar moves when the music is heard.

  **Every layer's sound plays together.** The preview mixes each audible layer — an audio layer, and a video layer whose clip carries sound — held to the transport through play, pause, scrub, frame step and loop, under the transport row's own volume and mute, with each layer's fades heard as they will be written. The render carries the same mix: AAC in MP4 and the platform presets, PCM in the QuickTime presets, Opus in WebM, and a WAV beside an image sequence or any other output with no room for an audio track. The mix is exactly the graphic's length and a trimmed render hears what its frames show. A project with no sound renders no audio stream and no file beside it, exactly as before.

- A clip keeps its sound (milestone 48). A talking head placed as a video layer used to render silent: a clip was decoded for its frames only, and the platform presets wrote H.264 with room for AAC audio and nothing to put in it. A video layer now plays its own audio in the preview — in step with its in point, speed, start delay and looping, under the transport's volume and mute, and silent on a held frame, as an editing app is — and the render mixes it into the file: AAC in an MP4, PCM in the QuickTime presets, Opus in WebM, with the mix cut and padded to exactly the rendered range so a trimmed render hears what its frames show. **Volume and Muted sit on the layer's card**, travel with the layer everywhere it goes (projects, presets, collections, CSV batches and `@layers` on the command line), and a clip the library knows has no audio stream says "This clip has no sound." instead of showing a dead pair of controls. A project with no audible layer renders no audio stream at all, exactly as before.

- Hand-off, finishing social-ready export (milestone 20). A finished render's card hands the file to where it was made for: **Share…** opens the system share sheet with the rendered file (macOS, the one desktop platform with one; the button is not shown elsewhere), and **Open upload page** — offered when the render was aimed at a platform preset — shows the file in the file manager and opens that platform's own upload page in the browser, ready to drop. No accounts, no logins and no posting through anyone's API: nothing to store a token for, nothing to re-certify, and nothing that breaks when a platform changes its API or its terms. ADR 0020 records the choice, so the reasoning survives the first request for one-click posting. Both act only on renders this app made, like Reveal and Copy path; the window sends a platform preset's id, never a URL, and every upload page in the built-in list is held to https by its test.

- Platform presets, and warnings about where a render is going (milestone 20). Making something for TikTok used to mean setting four fields and remembering what that platform takes. There is a **Platform** chooser at the top of the Output tab now — TikTok, Instagram Reels, Instagram feed, YouTube Shorts, YouTube, X, LinkedIn, Facebook feed — and choosing one sets the aspect, the resolution, the frame rate and the encoder together, saying underneath what it set and what the platform takes: "9:16 · 1080 × 1920 · 30 fps · H.264 MP4 · up to 10:00 and 287 MB (limits checked 1 November 2026)". - A local log, and Copy diagnostics in the status items (milestone 8). ### Fixed

- **A quick command-line run no longer crashes Windows on its way out.** A run that ends within a moment of the app being ready — `--sample-media` with nothing to make prints its message and returns 2 at once — could end the process with 0xC0000005 instead: `app.exit` tore it down while Chromium's own start-up, its GPU process handshake, was still under way. A command-line run now waits for the GPU process to answer before exiting (no GPU to wait for is also settled, and five seconds is far past a handshake), so a quick run ends the way a long one does — after start-up — with its exit code kept.

- **The transport row keeps its controls apart on a narrow window.** With the loudness meter showing, the row's controls overlapped below about 1100 px — on CI's 1008 px window the Output tab's button sat over the project's name — and narrower still the status cluster's icons overflowed even with the meter away. The meter folds below 1150 px now, the way the tab labels and the library's counts already fold; Copy diagnostics leaves with the counts below 1040 px (it is in the Help menu too); and at the window's minimum the timecode gives up its fixed floor and the clusters sit closer. The audio-layer UI test measures the row at 1280, 1120, 1008 and 960 px wide rather than only at the default. Two inert narrow-window rules were also made to take effect (the volume slider's 56 px width was overridden by a later rule of equal specificity), and a pasted duplicate of the meter, LUT and keyframe styles inside the short-window block is gone.

- **A bundled item's library id no longer depends on where Pulp is installed.** An item's id is a hash of its key, and the key was its absolute path — so every bundled template, media file and Lottie took a different id in every checkout and every install, and on Windows a different one again for the separator. The bundled library is keyed by the item's path *inside* the app now, with `/` separators on every platform, so the id is the same everywhere. The twenty bundled Lottie animations felt it first: a Lottie has no manifest id of its own, so its manifest id is made from its library id, and the approved visual references matched nothing on another machine. Saved projects and collections that name a bundled item keep matching across machines for the same reason. The library cache is re-read once on first launch, since every bundled item has a new id.

### Fixed

- The preview no longer swallows what is done to it. The template page is an `<iframe>`, which took pointer events for itself, so anything aimed at the picture — a drop from the results, and the right-click menu on a template whose layers have not been added yet, when the layer overlay stands aside — went to the template's own document and was lost there. The picture is a picture now: every click, drag and right-click on it belongs to the stage.

- The category cards show Matching sets. The top-level card row skipped it — it gathers packs rather than types, so it had no scope to open on — caught by milestone 34's closing unit test (every top-level category a description, every category a thumbnail). Choosing its card or its browse row now shows everything that came from any set, through a new `pack:any` search term.

- The bar that resizes the collection tray no longer reaches past it. It carried a negative margin to cancel a padding that lives on the tray's body rather than on the tray itself, so it hung twelve pixels past either side, over the browse panel's splitter on one side and the window's edge on the other.

- The status bar's items line up and are one size. A button, a paragraph, a flex summary and three spans, some carrying icons, were aligned on their baselines — and a baseline depends on what is inside each one, so an item starting with an icon took its baseline from the icon — while each kind also brought its own text size and line height. The bar sets the text once and centers them now, and every item inherits it.

- A render no longer writes a blank first frame. `capturePage()` on an offscreen window hands back the last painted frame, and on a loaded machine the first capture of a render could be taken before the first draw had been composited — the surface was then still the blank page. Draining the paints a page load costs made it rarer but not impossible, and it would not reproduce off the CI runner. The first capture is now read before it is believed: if every pixel is transparent it is taken again, a paint cycle later, up to three times. A frame that really is blank answers the same way each time and is kept, so this costs a few milliseconds once per render and never a wrong frame; when a retry does change the answer, the render says so. The same check covers the sample-media stills and the first frame of a generated asset clip, where a blank capture would have been written out as the file itself (docs/platform-notes.md).

- A transparent HEVC clip is recognized as transparent. macOS keeps HEVC alpha in an auxiliary layer of the video track rather than in the pixel format, so the file reports `yuv420p` — exactly what an opaque H.264 reports — and a library scan called it opaque: no Alpha badge, no checkerboard behind its thumbnail, and `alpha:yes` passed it over, which matters now that assets are a kind of their own. Such a clip is now told apart by the layers ffmpeg reports for the stream, from the same probe the scan already runs, and a stereo pair (multilayer for a different reason) is still read as opaque (docs/platform-notes.md).

- The Parameters tab always ends with "Layout and timing". Most bundled templates say outright which settings belong there by naming it as a parameter's element, and the tab took that at face value and made it a card like any other, in the order it was declared — so Lower Third Bar read Name, Title, Panel, Layout and timing, then Logo, with a part of the graphic stranded after the card that is meant to close the tab. A parameter may still name it, and now joins the last card instead of making one, wherever it is declared; a layer actually called that keeps the name, as it always did.

- A render no longer mistakes a leftover paint for its first frame. `capturePage()` on an offscreen window returns the last painted frame, and the render asked for a repaint and took the next paint to be it — but loading the page, and handing a template its image-slot pictures, each queue paints of their own, and on a slow machine one of those could still be arriving and be taken for the frame just drawn. The capture then held the surface from before the draw: a blank frame. It needed a single-frame render to show, since any later frame covers for it, and the extra work of an image slot to be likely at all, which is why what failed was one row of the CSV batch on the macOS runner. The paints a load costs are now let through before the first frame waits for one of its own; and since on a loaded machine a paint can take longer to arrive than that drain first allowed for — the macOS runner still produced a blank Boardroom lower third at frame 90 — the drain now waits for the paint answering its own repaint request, behind which every earlier paint has already arrived, before it counts the stream as quiet (docs/platform-notes.md).

- The collection tray no longer keeps a stale message. "Every item now has those output settings.", "Saved as …" and "Rendering 3 items." used to stay on the status line after the collection was emptied, replaced or changed, describing something that was no longer there. A confirmation now fades after a few seconds and goes the moment the collection changes under it; an error waits until the next action, so it is not missed; and an empty collection says only "Nothing collected yet."

- A squeezed stage keeps its picture. With the collection tray open on a short window, the stage gave every pixel to its own transport, tools and item row and left the preview nothing: the picture went invisible under its "no room" rule and the stage could not be clicked at all. The picture now keeps a floor and the chrome around it gives way first; when even that cannot be met the stage says so instead of showing nothing, and the layer overlay stops taking clicks it could never act on. This is what had been failing on Windows CI, where the window is 1008 × 655 (docs/platform-notes.md).

- Clicking a layer on the stage selects it reliably, including on a small window. The overlay could hit-test what the preview had laid a frame ago — the page says it has drawn before it reports what it drew — so a click could land on where a layer used to be; the report now names its frame and the overlay waits for the matching one. And a hit no longer has to be pixel-exact: on a preview a few hundred pixels wide a line of type is a few pixels tall, so a click within four screen pixels of a layer takes it. Found on Windows, where the CI window previews a 1920-pixel frame about 157 px wide (docs/platform-notes.md).

- The results grid no longer leaves a band of empty space under every wide card. One square or portrait item anywhere in the results — a 512 × 512 logo was enough — used to set the row height for the whole grid, so each wide card's picture and text sat in the top half of its cell. A grid that mixes shapes now lays out at 16:9, with a taller picture contained in the same box and its Vertical badge still saying what it is; the taller pitch is kept for a set that is square or taller all through, where every card needs the height.

- The preview answers even when the window is occluded or the frame has no screen time. Chromium throttles rendering for a window it believes no one can see — a covered window, a CI runner's desktop — and `requestAnimationFrame` then never fires, so the template page could never say a frame was drawn: the frame asked for never arrived and the stage's watchdog let request after request go. The window now opts out of background throttling, and the bridge's after-draw wait of two animation frames is bounded at a quarter of a second — the draw itself has already happened when the wait starts — so a frame is declared drawn rather than held forever (docs/platform-notes.md, "A throttled renderer runs no animation frames at all").

### Added

- Pulp has its own application menu on every platform — the macOS menu bar, a menu bar in the window on Windows and Linux — where there was Electron's default, named "Electron". **Pulp** (macOS) with About, Hide and Quit; **File** with the project actions and Open Recent, Add Library Folder…, Add Sample Media, Import and Export Pack…, Render… and Render All; **Edit** with Undo and Redo on Pulp's own history, Cut, Copy, Paste, Select All and Find Category; **View** for the browse panel, the preview and the collection tray, grid or rows, card size and full screen, with Reload and Developer Tools only in a development build; **Playback** for play and pause, stepping a frame, Set In, Set Out and Loop; and **Window** and **Help**, with the keyboard shortcuts and Copy Diagnostics.

  A menu item does exactly what the button for the same thing does, and is enabled only when that button is — the menu's state is read off the window's own controls, so a menu item and its button can never disagree. The shortcut list under Help is read off the menu itself, so it cannot drift from the keys. Undo and Redo show their shortcut without taking it, because inside a text field the field's own undo has to win; the rest take modified keys, since a key the menu registers fires inside a text field too and Space has to be able to type a space.

- A session can be saved as a **project**. A `.pulp` file holds the whole of it — everything collected, with each item's parameters, layers, placements and placed assets and its output settings, which library folders the project draws from, and where Render all last wrote — where a `.pulpcollection` held only the gathered items. New, Open, Save, Save As and Open Recent live behind the project's name in the status bar until the application menu arrives to hold them properly.

  Unsaved changes are visible and hard to lose: the project's name carries a dot while there are any, in the status bar and in the window title, and starting a new project, opening another or closing the window asks first — Save, Discard or Cancel. What counts as a change is what would be written: the library folders a project records are a note about the computer rather than about the work, so adding a folder is not an unsaved change and a project opened on a machine with different folders does not claim to have one.

  A project is written to a recovery file while it has unsaved changes and the file is cleared the moment they are saved, so a session that ends suddenly is offered back the next time Pulp starts — once, with the time it was taken and the file it belongs to.

  Collection files still open, as a project holding their items, and can be saved on as projects; a project can still be saved out as a `.pulpcollection` for anyone on an older build, by naming the file that way.

- Media that moved is flagged and can be **relinked** rather than quietly failing. Collected items now record where their file was as well as its library id, so an item the library cannot answer for still knows what it was and where it lived. Relinking one asks where it is now, brings its folder into the library and rebinds it — and because finding one file says where its whole folder went, every other missing item that moved the same way is rebound in the same step. A file that was renamed rather than moved says nothing about its neighbors, so only that one is relinked; guessing from a rename would bind items to the wrong files.

- A layer can be given a look of its own. Under **Look** in its card: opacity; a drop shadow with its color, distance, angle and softness; an outer glow; an outline — a stroke around type, a frame around a picture; a blur; a blend mode (Normal, Multiply, Screen or Overlay); and a color adjustment of brightness, saturation and a tint. Pictures and clips also take rounded corners and soft edges. Every size is a share of the frame, so a look reads the same at every resolution and shape, and it is drawn by Pulp around the template's own draw of the layer, so templates need no changes. A layer with a look is painted once and composited once, so half opacity is half opacity whatever else is on. The shadow and glow a picture could already be given are looks now, read as the same shadow and glow they always drew, so saved work is unchanged; the Shadow and Glow buttons on a layer's picture are gone, their work done under Look. A blur, a shadow and soft edges on a 720p clip in a 1080p render cost nothing measurable over the plain clip, since the canvas does them on the GPU.

- A bar per layer under the scrub bar shows when each layer is on screen, lined up under the scrub bar's own scale so a start can be read against the graphic's in, hold and out above it. Its ends drag, or step by the arrow keys — a tenth of a second, a second with Shift — and the time its entrance and exit take is shaded at either end. Clicking a bar selects its layer, as clicking it on the stage does, and the bar and the layer's Start and End fields are two views of one setting.

- A CSV batch can set the rest of what a layer carries: a `<layer> settings` column takes a JSON object per row — a span, transitions, a look, a placement or hidden — beside the column that sets the layer's words or its clip. With that, everything a layer can be given travels everywhere a layer does: saved presets, collection items and `.pulpcollection` files, `--param @layers` on the command line, a CSV batch, the render cache key and undo.

- A layer can say how it arrives and how it leaves. A layer used to take its movement from the template, or carry a single entrance override — Fade, Slide, Scale or None — with nothing at all to say about going. Its card now has an In and an Out, chosen separately, each with its own length in seconds, and a new **Wipe** that uncovers the layer from an edge instead of fading it, so it reads over any background. Slide and Wipe take the edge they travel from; left to itself that is the way the stack goes, which is what a slide always did.

  The entrance replaces the template's movement for that layer and the exit is multiplied into whatever was already there, so one end can be the person's and the other the design's. Both are timed against the layer's own start and end, and both are held inside them: two ends that together ask for more room than the layer has on screen are shortened in proportion rather than one eating the other. - A layer can say when it comes and when it goes. Every layer used to be on screen for the whole graphic, and the only timing a person could give one was a delay on its entrance. A layer's card now carries a Start and an End under Advanced, and the layer is drawn between them and nowhere else — so a lower third's second line can arrive a beat after the first, and a credit can leave before the strap does.

  Both are seconds of the graphic **as it is watched**, not of the template's own clock, which the length control let differ. Someone who wants a line two seconds in means two seconds into what they are watching, so a line set to run from 2 s to 4 s still arrives at two and leaves at four when the same graphic is stretched to twenty. The layout does not shift as layers come and go — a layer waiting its turn keeps the room the stack gave it — and a start or an end can shorten a layer's time on screen but never take it away altogether: a start past the end of the graphic is held back to the last moment of it, because a layer that should not be there at all is hidden, which says so plainly. A layer nobody has timed is stored exactly as it was before.

"HEVC (alpha, macOS only)": .mov with an HEVC alpha layer through Apple VideoToolbox at quality 80 and alpha quality 0.9, tagged `hvc1` and Rec.709. Presets whose encoder the installed ffmpeg lacks are listed as unavailable with the reason, so HEVC shows why it cannot be used on Windows and Linux. Decision record 0005 explains why the HEVC encoder is fed 4:4:4 Y'CbCr rather than BGRA.
- Render queue: clicking Render asks where to save and queues the job, so several renders can be lined up and run one after another. Each job shows its own progress, result or error, and can be canceled; finished jobs stay listed until cleared.
- Per-frame render timeout (10 seconds by default) and a 30-second load timeout, so a hung template stops the render with a clear message instead of hanging it.
- Headless mode flags `--library <folder>` (extra template folder for one run) and `--frame-timeout <seconds>`.
- End-to-end render test (`npm run test:e2e`, also part of `npm test`): renders the samples to ProRes 4444, VP9 WebM, PNG sequence and H.264 and checks frame count, size and alpha with ffprobe, plus the error and timeout paths. Skipped when Electron, ffmpeg or ffprobe is missing.
- Size verification at 4K (3840x2160), 8K (7680x4320) and portrait 1080x1920 for vertical video. Three size-probe fixture templates under `tests/e2e/templates` render as PNG sequences and the test reads pixels back to confirm dimensions, orientation and that the frame was captured at full size; 8K ProRes 4444 and portrait H.264 cover the video presets at those sizes.
- End-to-end check that frames stay pixel-exact with the display scaled to 150% (Chromium's `--force-device-scale-factor=1.5`), and a CI job on `windows-latest` that installs ffmpeg and runs the whole suite including the end-to-end tests. `PULP_E2E=1` makes the suite fail instead of skipping when a tool is missing. The job passes on Windows with ffmpeg 9.0.2, which verifies the renderer there: scale 1 capture, raw frames, Rec.709 output and the 150% scaling check.
- End-to-end check that a 2x offscreen surface (simulated with `PULP_OFFSCREEN_SCALE=2`) fails the render with the capture-size message instead of producing resized frames.

### Changed

- QuickTime Animation output carries a `colr` atom declaring full-range RGB (GBR matrix, BT.709 primaries and transfer); MOV has no range flag for RGB codecs, and without the atom Resolve's Data Levels Auto treated the file as video range and scaled the alpha. PNG sequences carry the same frame tags, which PNG ignores.
- Video presets (ProRes 4444, ProRes 422 HQ, H.264, VP9) now convert to Rec.709 with the BT.709 matrix at limited range and tag the output BT.709 primaries, transfer and matrix, limited range. Before, files carried no color information and ffmpeg used its BT.601 default, which shifted saturated colors in editors. Alpha templates are composited over the background in RGB before the conversion. PNG sequences stay full-range sRGB. Decision record 0004 has the reasoning, including why the transfer is tagged BT.709 rather than sRGB.
- Frames travel to ffmpeg as raw BGRA pixels instead of PNG images, removing a PNG encode in the app and a decode in ffmpeg per frame. Frames from alpha templates are unpremultiplied in ffmpeg, so semi-transparent edges keep their color. `--frame-format png` keeps the old path for comparison, and headless mode prints elapsed time and frames per second. Measurements are in `docs/system-design.md`; the reasoning is in decision record 0003.
- The offscreen render window is created at device scale factor 1 on purpose (Electron's `offscreen.deviceScaleFactor`), so templates see `devicePixelRatio` 1 and frames are captured at exactly the declared size on HiDPI displays. A capture at any other size now fails the render with a clear message instead of being silently resampled.
- When a template throws during a render, the error names the template, the frame, the error type and the file and line inside the template.
- The template bridge script is injected on one line so line numbers in template errors match the template's own file.

### Fixed

- The template page now says what frame it has drawn (`window.__pulp.drawn`), and the stage puts its frame state on the preview box, so a test — or a person — waits for the frame it changed rather than guessing how long a two-core machine takes. Four Windows end-to-end failures were canvases read one change too early.

- A bundled font would not load in a template page on Windows, and the frame waited for it for ever, so a line added to a template never appeared. A font load is a CORS request even to the page's own origin, and these schemes enforce CORS; the answer now says who may read it instead of relying on two custom-scheme origins comparing equal, and `font-src` names the scheme as well as `'self'`. The bridge's wait for a face is bounded at three seconds, so a font that cannot be fetched costs one frame in the fallback rather than every frame. The layers tests put the template's own layers back even when they fail, so one failure no longer wrecks the next test.

- The preview could freeze for good. A frame is drawn when the template page answers, and a page with no room on screen — the stage collapsed, squeezed to nothing, or the window too short — runs no animation frames and never answers, after which every later frame was parked behind the one in flight and the preview showed one stale picture until the app was restarted. Each request now has a four-second watchdog: the stage lets the unanswered one go and asks again, so the preview catches up by itself as soon as it has room. This is what made three Windows end-to-end tests fail on the small display the runner has.

- The stage preview could be squeezed out of shape. Its box took the full width at the picture's ratio and then had its height clamped, so while the window loaded or a region resized the box lost its shape and the template or media inside was stretched. The box is now sized from the room it has: the largest box of the picture's own ratio that fits, letterboxed or pillarboxed, and not drawn at all when there is no room — for 16:9, 9:16, 1:1 and 4:5 templates and for media alike. A UI test squeezes the stage narrow, short and a step at a time and checks the drawn ratio after every change.
- The results list kept no minimum height. On a short window — a 1024 × 768 display, or any window once the collection tray opened — the stage's share of the center column could squeeze the list to a few pixels, which is what the Windows end-to-end failures were: a list too short to scroll through, not an app that had stopped answering. The results now keep at least 160 px, the stage gives way first and clips rather than painting over them, and the tray is capped so the center column keeps room for the search bar, the results and about 180 px of stage. The UI test emulates a short window and checks all three, and its result sweeps are bounded by the list's own length instead of a fixed step count.
- A window asking about a path that does not exist (Copy path, Reveal or a drag of a file that is not the app's) left an unhandled rejection in the main process: the cache check started resolving the path before it had awaited the cache folder. It resolves the folder first now.
- The test suite can no longer stall on a child process. Every ffmpeg, ffprobe, Electron and build run the end-to-end tests start goes through one runner with no stdin, a time limit and a whole-tree kill (which Windows needs: killing Electron's main process leaves its helpers holding the pipes), ffmpeg is always started with `-nostdin`, the CI jobs have time limits, and on CI the reporter names each test as it starts, so a stall says where it is.
- The Info tab's Location row read `boardroom\lower-third` on Windows. It is a breadcrumb inside the library folder, not a path, so it now uses forward slashes on every platform; the tooltip keeps the native path.
- `settings.json` (library folders, recent colors) is written atomically: a temporary file is renamed over the old one, so a crash or a reader during a save sees the old or the new file and never a half-written one that would lose the library folder list. Changes that arrive close together are queued so none is lost.
- The end-to-end tests' cleanup no longer fails on Windows with EBUSY: they wait for the app to exit and delete scratch folders with retries, since Windows refuses to delete files a just-killed process still holds.
- The first captured frame could be blank or one frame stale on slow machines (seen on Windows CI with trimmed and flattened renders). The template bridge now resolves two animation frames after drawing, and the renderer forces a repaint and waits for the paint event before each capture, so the capture always holds the frame that was just drawn. The offscreen window's begin-frame rate is raised to 240 so the extra waits cost about 4 ms, which makes renders faster than before the fix (lower third: 67 frames/s raw against 54).
- Raw frames with ffmpeg 8.1 and later. Those versions negotiate an alpha mode on filter links and treat untagged raw input as straight alpha, so ffmpeg premultiplied the already premultiplied frames before the unpremultiply step: semi-transparent pixels came out dark (a white 85% panel read 216 instead of 255) and every color one step low. The renderer now detects alpha mode support and tags raw frames with their measured layout first. Verified with ffmpeg 8.0 and 9.0.2; found by the Windows CI job.
- Raw frames no longer depend on assumptions about the capture bitmap. The renderer measures the byte order and premultiplication of `toBitmap()` output with a probe page before the first render (Electron documents the layout as platform-dependent), passes the result to ffmpeg, and falls back to PNG frames with a warning if the bytes fit no known layout. The unpremultiply step is fed planar RGB explicitly so format negotiation cannot pick a lossy Y'CbCr intermediate.
- Canceled or failed renders no longer leave partial output files behind. Files that existed before a render without overwrite are kept.
