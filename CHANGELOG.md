## [Unreleased]

### Added

- A right-click menu on the stage (milestone 39). The edits a layer needs most are where the pointer already is, instead of several clicks away in the Parameters tab. Right-click a layer — which selects it, as a left-click does — and the menu offers Cut, Copy, Paste, Duplicate and Delete; an Order submenu (bring forward, send backward, bring to front, send to back); Copy Look and Paste Look, so a shadow, a glow or a blend carries from one layer to another; Start at Playhead and End at Playhead, which move one end of the layer's window to where the playhead is, through the same rule the bar under the scrub bar uses; and Reset Layer, which takes off what you gave it — where you put it, when it comes and goes, how it arrives, how it looks — and keeps what it is. On a line of type it also offers Edit Text, which brings the Parameters tab forward with the caret in the words, selected and ready to be typed over; on a picture, Replace Image…, and on a clip, Replace Clip… — each opening that layer's own chooser. Each is offered only on the kind of layer that has it. Right-click bare picture and it offers Add Text Here, an Add Asset Here submenu of your library's pictures and clips with the most recently used first, Paste, Add to Collection, a Background submenu and Theater — the last three for a clip or a still on the stage too, which have no layers at all. Whatever is added lands where you clicked rather than at the end of the stack, and the Parameters tab comes forward on it ready to be typed over. A duplicate sits right above its original with a name of its own, a cut layer pastes back into the block it came from, and a layer the template marks required can be copied but not cut or deleted. Every edit is an ordinary edit: one undo step, redrawn through the one preview pipeline. A line added anywhere — the menu, or the Parameters tab's own Add button — now arrives carrying the word "Text" rather than empty, since a layer drawing nothing takes no room in the stack and so could not be placed or taken hold of. The stage background gains a fourth choice, mid-grey, beside the checkerboard, black and white: black flatters a bright edge and white a dark one, and grey is the neutral a soft edge or a key is really judged against. It is on the stage's own controls as well as in the menu, and in a new Stage Background submenu under View. The menu opens from the keyboard too — Shift+F10 and the Menu key, on the selected layer, appearing beside what it is about — and walks with the arrow keys, Right and Left for submenus, Enter to choose and Escape to close, giving the keyboard back to the stage afterwards. The menu is built from the application menu's own command list — the same commands, enabled by the same flags, run by the same dispatcher, and the Edit menu grew a Layer submenu offering all of them — so nothing can be reachable from one and not the other, which a test checks rather than a convention (ADR 0017).

- Lottie animations, the first three steps (milestone 35). A `.json` Lottie — the animated vector format After Effects exports through Bodymovin — or a `.lottie` archive in a library folder is read as a template: its own size, frame rate and length become the manifest, every built-in aspect is declared so a Fit setting can fit, fill or centre it in a frame of another shape, and its type and themes come from its folders as a clip's do. A `.json` is told from other JSON by its first few kilobytes, so settings files are never read whole. It gets a poster and a hover-scrub strip like any template, plays and scrubs on the stage, and renders through the same renderer with alpha: lottie-web (MIT, its light build, which runs under the template CSP without `eval`) is stepped to each frame rather than played, so a render is frame accurate at any output rate, and the end-to-end test reads a keyframed square's pixels back where they must be. What the file exposes is in the Parameters tab — its slots where the author made some, otherwise a Text field per static text layer and each distinct fill, stroke, solid and text colour once, saying where a palette colour is shared — and saved with the item like any other parameter. The Info tab names the source, the markers, what is editable, and what the player does not draw: expressions, layer effects, 3D and cameras, audio, and fonts and pictures the file would fetch from the web. A Lottie cannot go into a template pack (it is one file in a folder of other things); export asks for the file to be shared itself. Fonts and images inside, timing from markers, placing on the stage, the sample animations and the remaining limits are the rest of the milestone.

- A bigger stage (milestone 38). The inspector's Parameters, Output and Info are three buttons in the transport row now; choosing one opens a drawer that rises from the row over the results — never over the stage, so the picture stays in view while a title is typed. - Recolor for media renders: a tint at render time draws the picture's luminance in one colour, alpha kept — a light leak or a texture matched to a palette — set in the Output tab beside the other media options and applied inside a loop's unit so every repeat matches.

- Every layered still, not only Photoshop. An OpenRaster (`.ora`) reads exactly as a `.psd` does — layers, groups, visibility, opacity, blends, toggling, placing whole or split. A Krita (`.kra`) lists its structure over its merged picture, with the honest limit that Krita's own tile format is not read — export `.ora` for workable layers. An SVG's top-level layers — the named groups Illustrator writes, the layers Inkscape marks — show and hide like any other file's, and the picture is drawn by the renderer itself, sharp at any render size; linked pictures beside the file are inlined, scripts never run, fonts are named. An `.ai` saved with PDF compatibility (Illustrator's default) and any layered PDF read through pdf.js 6 (in a sandboxed window, eval off): the optional content groups are the layers, page 1 draws over transparency, and an `.ai` saved without compatibility is named with how to re-save it. Files Pulp does not read — Affinity, GIMP `.xcf`, Sketch, Procreate, EPS — are named in the library with the export that works instead of being skipped silently.

- Library media renders itself. A clip, a still, a layered file or a sound chosen in the library, or collected in the tray, renders with the same presets a template does, so a collection is never a dead end and "not renderable yet" is gone. The Output tab takes a media item as it takes a template: its preset, frame rate, size, in and out points, and three more — a length (a still is held for it; a clip or a sound longer than itself loops to it, the end crossfading into the start so the join is seamless, with the crossfade's seconds as a field or 0 for a plain repeat), a speed (which takes the sound with it), and a matte file. A sound renders with audio presets of its own — WAV at 16 or 24 bit, AAC, MP3 — with the sample rate and channels to choose. A layered Photoshop file renders as the picture it was collected as, its hidden layers left out. Render all, Prepare for drag and the headless `--collection` all take media.

- A matte file. Any render, template or media, can write a second file beside itself, `<name>-matte<ext>`, holding the alpha as grey in the same codec — for HEVC in Premiere Pro, WebM, and any editor that reads no alpha. A sequence writes a matte sequence.

- Layered Photoshop files. A `.psd` in a library folder is read as a stack of layers — names, order, groups, visibility, opacity and blend modes — by Pulp's own reader — raw, RLE or zip-compressed layer data, 8 or 16 bits — so a layered still from a stock library can be used without flattening it first. The grid and the stage show its composite; the Info tab lists its layers with a box to show or hide each, and the stage follows. Dropped on a template it is one picture, starting with the layers hidden while it was browsed, and the hidden list travels in the image value like any other edit — presets, collections, undo and the render cache key all carry it. Added to the collection unplaced, the item keeps that picture too: the card says how many layers are hidden and shows the composite as collected, and choosing the card brings the list back. "Split into layers" turns that picture into one image layer per shown layer, each keeping its place, to be moved and styled on its own. Layer effects, smart objects, adjustment and fill layers, masks, clipping and the few blend modes with no canvas equivalent are named on the layer rather than dropped (every mode a canvas draws natively — multiply through luminosity — is drawn); the picture Photoshop stored in the file stands in where layers cannot be drawn. Reading only: Pulp never writes a `.psd`.

- The browse panel says what things are. Its top level is plain categories in the order a stock library leads with — Lower thirds, Titles and openers, End cards, Matching sets, Animated backgrounds, Still backgrounds, Overlays and frames, Transitions and wipes, Design elements, Effects, Objects, Stock video, Photos and stills, Music, Sound effects — with the taxonomy's types beneath the ones that gather several and packs beneath Matching sets, then Quick access and My folders. Themes and styles are no longer trees of their own: they are the "For…" and "Look" chips in the search bar, which narrow whatever category is chosen (Lower thirds › For: Wedding › Look: Elegant). Every category has a one-line description, shown under the results heading and on hover; choosing one with nothing searched shows its subcategories as cards with a picture and a count, and with nothing chosen the categories themselves. The start screen's "What are you making?" opens the matching category with its For chip set. Saved searches, settings and the taxonomy's ids are unchanged.

- Template posters show the thing. The poster used to be the middle frame always, which for most overlays was a frame with little drawn; it is now chosen from eight frames spread over the timeline by how much each shows, a manifest may name its best moment with `posterAt`, a transparent template's poster is cropped to what it draws plus a margin, and a transparent template's card sits on a quiet backdrop tinted by category rather than bare checkerboard — the Alpha badge says it is transparent. The stage and the Info tab keep the full frame.

- A start screen, shown at launch and from File → Home, with a "Show at startup" switch. It offers a new project blank or by shape (16:9, 9:16, 1:1, 4:5 — the choice presets the Output tab's aspect for every template that draws it); six example projects built from the bundled templates, each opening as a copy so the example stays as it was; the recent projects with thumbnails, last-opened dates and pinning, where a missing file says so and can be relinked; a Learn section with a guided five-step tour of the window (replayable from Help → Take the Tour), "What's new" read from this changelog's latest release, and the keyboard shortcuts; a first-run checklist (FFmpeg found, a library folder added, sample media made) whose undone items are buttons that do it, with the library at a glance beside it; and "What are you making?" — an interview, a sports opener, a wedding, a social clip, a news package — each folding the browse panel to the category that serves it.

### Security

- Electron 44.9.1, which carries the mitigation for compromised eMudhra intermediate certificates (GHSA-jr5w-w6x2-84p9) that 44.9.0 lacked. CI now audits dependencies and fails on a known high or critical advisory.

### Fixed

- The preview no longer swallows what is done to it. The template page is an `<iframe>`, which took pointer events for itself, so anything aimed at the picture — a drop from the results, and the right-click menu on a template whose layers have not been added yet, when the layer overlay stands aside — went to the template's own document and was lost there. The picture is a picture now: every click, drag and right-click on it belongs to the stage.

- The category cards show Matching sets. The top-level card row skipped it — it gathers packs rather than types, so it had no scope to open on — caught by milestone 34's closing unit test (every top-level category a description, every category a thumbnail). Choosing its card or its browse row now shows everything that came from any set, through a new `pack:any` search term.

- The bar that resizes the collection tray no longer reaches past it. It carried a negative margin to cancel a padding that lives on the tray's body rather than on the tray itself, so it hung twelve pixels past either side, over the browse panel's splitter on one side and the window's edge on the other.

- The status bar's items line up and are one size. A button, a paragraph, a flex summary and three spans, some carrying icons, were aligned on their baselines — and a baseline depends on what is inside each one, so an item starting with an icon took its baseline from the icon — while each kind also brought its own text size and line height. The bar sets the text once and centres them now, and every item inherits it.

- A render no longer writes a blank first frame. `capturePage()` on an offscreen window hands back the last painted frame, and on a loaded machine the first capture of a render could be taken before the first draw had been composited — the surface was then still the blank page. Draining the paints a page load costs made it rarer but not impossible, and it would not reproduce off the CI runner. The first capture is now read before it is believed: if every pixel is transparent it is taken again, a paint cycle later, up to three times. A frame that really is blank answers the same way each time and is kept, so this costs a few milliseconds once per render and never a wrong frame; when a retry does change the answer, the render says so. The same check covers the sample-media stills and the first frame of a generated asset clip, where a blank capture would have been written out as the file itself (docs/platform-notes.md).

- A transparent HEVC clip is recognised as transparent. macOS keeps HEVC alpha in an auxiliary layer of the video track rather than in the pixel format, so the file reports `yuv420p` — exactly what an opaque H.264 reports — and a library scan called it opaque: no Alpha badge, no checkerboard behind its thumbnail, and `alpha:yes` passed it over, which matters now that assets are a kind of their own. Such a clip is now told apart by the layers ffmpeg reports for the stream, from the same probe the scan already runs, and a stereo pair (multilayer for a different reason) is still read as opaque (docs/platform-notes.md).

- The Parameters tab always ends with "Layout and timing". Most bundled templates say outright which settings belong there by naming it as a parameter's element, and the tab took that at face value and made it a card like any other, in the order it was declared — so Lower Third Bar read Name, Title, Panel, Layout and timing, then Logo, with a part of the graphic stranded after the card that is meant to close the tab. A parameter may still name it, and now joins the last card instead of making one, wherever it is declared; a layer actually called that keeps the name, as it always did.

- A render no longer mistakes a leftover paint for its first frame. `capturePage()` on an offscreen window returns the last painted frame, and the render asked for a repaint and took the next paint to be it — but loading the page, and handing a template its image-slot pictures, each queue paints of their own, and on a slow machine one of those could still be arriving and be taken for the frame just drawn. The capture then held the surface from before the draw: a blank frame. It needed a single-frame render to show, since any later frame covers for it, and the extra work of an image slot to be likely at all, which is why what failed was one row of the CSV batch on the macOS runner. The paints a load costs are now let through before the first frame waits for one of its own; and since on a loaded machine a paint can take longer to arrive than that drain first allowed for — the macOS runner still produced a blank Boardroom lower third at frame 90 — the drain now waits for the paint answering its own repaint request, behind which every earlier paint has already arrived, before it counts the stream as quiet (docs/platform-notes.md).

- The collection tray no longer keeps a stale message. "Every item now has those output settings.", "Saved as …" and "Rendering 3 items." used to stay on the status line after the collection was emptied, replaced or changed, describing something that was no longer there. A confirmation now fades after a few seconds and goes the moment the collection changes under it; an error waits until the next action, so it is not missed; and an empty collection says only "Nothing collected yet."

- A squeezed stage keeps its picture. With the collection tray open on a short window, the stage gave every pixel to its own transport, tools and item row and left the preview nothing: the picture went invisible under its "no room" rule and the stage could not be clicked at all. The picture now keeps a floor and the chrome around it gives way first; when even that cannot be met the stage says so instead of showing nothing, and the layer overlay stops taking clicks it could never act on. This is what had been failing on Windows CI, where the window is 1008 × 655 (docs/platform-notes.md).

- Clicking a layer on the stage selects it reliably, including on a small window. The overlay could hit-test what the preview had laid a frame ago — the page says it has drawn before it reports what it drew — so a click could land on where a layer used to be; the report now names its frame and the overlay waits for the matching one. And a hit no longer has to be pixel-exact: on a preview a few hundred pixels wide a line of type is a few pixels tall, so a click within four screen pixels of a layer takes it. Found on Windows, where the CI window previews a 1920-pixel frame about 157 px wide (docs/platform-notes.md).

- The results grid no longer leaves a band of empty space under every wide card. One square or portrait item anywhere in the results — a 512 × 512 logo was enough — used to set the row height for the whole grid, so each wide card's picture and text sat in the top half of its cell. A grid that mixes shapes now lays out at 16:9, with a taller picture contained in the same box and its Vertical badge still saying what it is; the taller pitch is kept for a set that is square or taller all through, where every card needs the height.

- The preview answers even when the window is occluded or the frame has no screen time. Chromium throttles rendering for a window it believes no one can see — a covered window, a CI runner's desktop — and `requestAnimationFrame` then never fires, so the template page could never say a frame was drawn: the frame asked for never arrived and the stage's watchdog let request after request go. The window now opts out of background throttling, and the bridge's after-draw wait of two animation frames is bounded at a quarter of a second — the draw itself has already happened when the wait starts — so a frame is declared drawn rather than held forever (docs/platform-notes.md, "A throttled renderer runs no animation frames at all").

### Changed

- Eleven bundled templates no longer offer a "Hold, seconds" setting: the citation callout, the city lights and civic openers, the donation, fitness and lap counters, the handle and profile cards, the poll strip, the hairline lower third and the kicker title. The graphic's length is the control now, and it does more than the setting did — the setting was clamped inside the template's own duration, so it could shorten the hold but never carry the graphic past the length it was drawn at, while Length goes to ten minutes. Each one keeps the hold its design shipped with, so they draw the same pixels at their own length as before.

- Add sample media is about twice as fast. The catalogue's 304 files were made strictly one after another, which left the machine idle for most of it: 175 of them are sounds, and a sound is an ffmpeg subprocess this process only waits on. Sounds now run several at a time, and the drawn files — stills, assets and clips, each through an offscreen window — keep going one at a time alongside them, since several offscreen windows competing for the compositor is what makes a capture come back stale. The whole catalogue takes 54 s where it took 121 s, and comes out the same file for file. This is also what had the end-to-end test running close to its nine-minute bound on a busy machine.

- The Festival set no longer claims every celebration at once. Its pack handed all fifteen pieces all seven occasions, so a Valentine's search turned up the Christmas ribbon and a graduation search turned up everything. The pack now imposes nothing and each piece says what it fits: the midnight countdown is New Year, the confetti burst a birthday, the ribbon a wedding, the sparkle flash Valentine's, the ident Christmas, the end card a graduation, and the nine general pieces are simply Holiday. The occasions keep their depth through assets of their own instead — twenty-one new CC0 motifs and sounds across the six, from sleigh bells and a cork pop to a mortarboard and chapel bells — so every theme in the tree still stands six deep.

- A browse node's count is read as well as seen. The tree's counts are drawn beside each label and hidden from screen readers, which left a node announced as "Lower third" with no idea how much was in it; the node's accessible name now carries it in words — "Lower third, 5 items", "Favorites, 1 item".

- Every bundled template's Parameters tab is organised by part of the graphic. Only Title Card and Lower Third Bar named their parts; the other 89 kept a flat "Colors" group, which tells you what the controls are — which you can already see — and not what they affect. All 553 of their settings now name the part they belong to, in each template's own words: a newsdesk lower third offers Name, Topic, Live flag, Accent, Panel, Text, Logo and Layout and timing; a counter's start, target, decimals, prefix and suffix are one card of Figures; an overlay whose only subject is itself puts its amount, size and softness under its own name. A test holds every bundled template to it, so none can go back to a group named after a kind of setting.

- A session can be saved as a **project**.   Collection files still open, as a project holding their items, and can be saved on as projects; a project can still be saved out as a `.pulpcollection` for anyone on an older build, by naming the file that way.

- Media that moved is flagged and can be **relinked** rather than quietly failing. - A layer can be given a look of its own. Pictures and clips also take rounded corners and soft edges. Every size is a share of the frame, so a look reads the same at every resolution and shape, and it is drawn by Pulp around the template's own draw of the layer, so templates need no changes. A layer with a look is painted once and composited once, so half opacity is half opacity whatever else is on. The shadow and glow a picture could already be given are looks now, read as the same shadow and glow they always drew, so saved work is unchanged; the Shadow and Glow buttons on a layer's picture are gone, their work done under Look. A blur, a shadow and soft edges on a 720p clip in a 1080p render cost nothing measurable over the plain clip, since the canvas does them on the GPU.

- A layer can say how it arrives and how it leaves. - A layer can say when it comes and when it goes. Every layer used to be on screen for the whole graphic, and the only timing a person could give one was a delay on its entrance. The app now says that editors link to prepared files and that clearing or evicting the cache takes those clips offline.
- Drag renders into your editor. A finished job in the queue can be dragged straight into an editing app's bin or timeline, and "Prepare for drag" renders the selected template with the current parameters, preset and options into a cache so the drag handle can carry it; an identical render is reused rather than redone. The cache folder can be changed, has a size limit (oldest files go first) and can be cleared.
- Template packs. Import a `.zip` or folder with a `pack.json` and one folder per template: a preview shows the pack's name, author and license, each template's id, license and size, and what will happen; licenses that are missing, non-open or unknown are flagged; a template whose id is already in your library folders is skipped, one installed from an earlier pack can be kept or replaced. Packs install into the app's user data, never into library folders, and join the library at once. Export the listed templates as a pack with a name, author and license. The format is in the template specification.
- Saved parameter presets per template: name the current values and save; apply from a list as an undoable step; saving over an existing name asks first. Only values that differ from the template's defaults are stored, in one file per template in the user data folder, and parameters a template no longer has are ignored.
- Batch rendering from CSV, in the inspector and as `--batch file.csv` headless: one render per row, columns matched to parameter ids or labels ignoring case, a `name` column naming the jobs and files, unknown columns listed as a warning before anything is queued, one folder asked for once.
- Your own tags and favorites on any library item, shown in the stage as chips (folder and manifest tags are listed too but cannot be removed) with a field to add more, and a star to favorite. Both are kept in the library database, survive folders going offline, and work in search: `tag:` finds your tags, `favorite:yes` lists favorites, `recent:10` lists the ten items most recently selected or rendered.
- Thumbnails in the library list: a poster frame for each template (rendered at mid-progress with default parameters) and a frame for each video and image (a tenth into the clip), made in the background, fitted into 240 px, cached in the user data folder and redone only when the item changes. Shown over a checkerboard so alpha is visible; audio shows a marker instead.
- Media metadata. Library media is probed with ffprobe in the background after each scan (duration, picture size, frame rate, codecs, alpha), shown in the list and details, cached by file size and time so only changed files are probed again. New search filters use it: `duration:>5` (also `<`, `>=`, `<=`, `=` and `5-10`), `width:`, `height:`, `fps:`, `res:1080p` (and `4k`, `uhd`, `8k`, `hd`, `fhd`), `codec:prores`, `alpha:yes`; templates answer the same filters from their manifests.
- Media preview. Selecting a video, image or audio file in the library shows it in the stage, with playback and seeking for video and audio. Files are served to the app window through a dedicated `pulp-media://<id>/` scheme that addresses items by library id, resolves the real file location and refuses anything outside the registered library folder (including symlinks that point elsewhere), serves only recognized media types, answers byte ranges, and returns a plain 404 for unknown ids, offline folders and missing files. Template pages cannot load from it.
- Persistent library index. Scanned items are kept in `library.sqlite` in the user data folder (`node:sqlite`, no native module; decision record 0007), so the app opens with its library at once and rescans only what changed: unchanged files and templates are kept without being read. Library folders are watched where the platform supports it, and the index is also refreshed when the window regains focus and when a folder that had gone missing is back. Items of a missing folder are shown as offline instead of being removed, so tags and favorites attached to them survive. Nothing is written into library folders. A synthetic library of 5,100 items scans in about 145 ms and rescans unchanged in about 105 ms.
- Decision record 0006: the UI stays plain DOM through milestone 3; the library milestone is the point to re-evaluate a component framework.
- Recent colors: each color field shows up to eight recently used colors, shared across templates and kept in `settings.json`; a committed color edit moves it to the front, and clicking a swatch applies it to that field.
- Parameter editing: number parameters with a range get a slider with direct entry; text parameters with a maximum length show a character counter. Undo and Redo (buttons, Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z or Ctrl+Y) record committed edits per template, with typing coalesced into one step; inside a text or number field the shortcut stays with the field's own undo. Each changed field shows a Reset, and Reset all clears the template; both are undoable. Edits and history are kept per template for the session.
- `docs/platform-notes.md`: the Electron, Chromium, ffmpeg, Windows and macOS findings behind the renderer (stale captures and the 60 Hz begin-frame cost, device scale, bitmap layout, ffmpeg 8.1+ alpha modes, color tags, Windows CI handling) with causes and fixes, so they are not re-solved.
- Color parameters have an alpha control. The native color input could only edit the RGB part and the alpha a template declared was kept but could not be seen or changed; each color field now has a slider for the alpha as a percentage, a text field for the whole `#RRGGBB` or `#RRGGBBAA` value, and a swatch over a checkerboard. A UI test drives the running app and reads the preview's pixels to confirm the alpha reaches the template.
- Render options, in the inspector and as headless flags: a frame-rate override (`--fps`) picked from the standard list (23.976, 24, 25, 29.97, 30, 47.952, 48, 50, 59.94, 60, 100, 119.88, 120) that samples the template at another rate over the same duration; the background color alpha templates are flattened over in presets without alpha (`--background #RRGGBB`); and in/out points (`--in-point`, `--out-point`), inclusive frames at the output rate entered as timecode `HH:MM:SS:FF` (three frame digits from 100 fps, semicolons for NTSC drop-frame), a frame number, or seconds such as `2.5s`. PNG sequences are numbered with the frame indices they hold. The inspector shows the resulting frames, rate and range, or the reason an entry is refused, and the queue validates before asking where to save. The preview's time display is timecode.
- `docs/nle-verification.md`: what is established about alpha (capture is premultiplied, every alpha preset is written straight), how a misread looks, a checklist for Premiere Pro, DaVinci Resolve and Final Cut Pro with a results table, and an alpha check test template (`tests/e2e/templates/alpha-check`) with an alpha ramp, 50% color patches, hairlines and moving text.
- Two output presets. "QuickTime Animation (alpha)": lossless RLE .mov with alpha for older workflows, full-range sRGB like PNG. "HEVC (alpha, macOS only)": .mov with an HEVC alpha layer through Apple VideoToolbox at quality 80 and alpha quality 0.9, tagged `hvc1` and Rec.709. Presets whose encoder the installed ffmpeg lacks are listed as unavailable with the reason, so HEVC shows why it cannot be used on Windows and Linux. Decision record 0005 explains why the HEVC encoder is fed 4:4:4 Y'CbCr rather than BGRA.
- Render queue: clicking Render asks where to save and queues the job, so several renders can be lined up and run one after another. Each job shows its own progress, result or error, and can be cancelled; finished jobs stay listed until cleared.
- Per-frame render timeout (10 seconds by default) and a 30-second load timeout, so a hung template stops the render with a clear message instead of hanging it.
- Headless mode flags `--library <folder>` (extra template folder for one run) and `--frame-timeout <seconds>`.
- End-to-end render test (`npm run test:e2e`, also part of `npm test`): renders the samples to ProRes 4444, VP9 WebM, PNG sequence and H.264 and checks frame count, size and alpha with ffprobe, plus the error and timeout paths. Skipped when Electron, ffmpeg or ffprobe is missing.
- Size verification at 4K (3840x2160), 8K (7680x4320) and portrait 1080x1920 for vertical video. Three size-probe fixture templates under `tests/e2e/templates` render as PNG sequences and the test reads pixels back to confirm dimensions, orientation and that the frame was captured at full size; 8K ProRes 4444 and portrait H.264 cover the video presets at those sizes.
- End-to-end check that frames stay pixel-exact with the display scaled to 150% (Chromium's `--force-device-scale-factor=1.5`), and a CI job on `windows-latest` that installs ffmpeg and runs the whole suite including the end-to-end tests. `PULP_E2E=1` makes the suite fail instead of skipping when a tool is missing. The job passes on Windows with ffmpeg 9.0.2, which verifies the renderer there: scale 1 capture, raw frames, Rec.709 output and the 150% scaling check.
- End-to-end check that a 2x offscreen surface (simulated with `PULP_OFFSCREEN_SCALE=2`) fails the render with the capture-size message instead of producing resized frames.

### Changed

- QuickTime Animation output carries a `colr` atom declaring full-range RGB (GBR matrix, BT.709 primaries and transfer); MOV has no range flag for RGB codecs, and without the atom Resolve's Data Levels Auto treated the file as video range and scaled the alpha. PNG sequences carry the same frame tags, which PNG ignores.
- Video presets (ProRes 4444, ProRes 422 HQ, H.264, VP9) now convert to Rec.709 with the BT.709 matrix at limited range and tag the output BT.709 primaries, transfer and matrix, limited range. Before, files carried no color information and ffmpeg used its BT.601 default, which shifted saturated colors in editors. Alpha templates are composited over the background in RGB before the conversion. PNG sequences stay full-range sRGB. Decision record 0004 has the reasoning, including why the transfer is tagged BT.709 rather than sRGB.
- Frames travel to ffmpeg as raw BGRA pixels instead of PNG images, removing a PNG encode in the app and a decode in ffmpeg per frame. Frames from alpha templates are unpremultiplied in ffmpeg, so semi-transparent edges keep their color. `--frame-format png` keeps the old path for comparison, and headless mode prints elapsed time and frames per second. Measurements are in `docs/system-design.md`; the reasoning is in decision record 0003.
- The offscreen render window is created at device scale factor 1 on purpose (Electron's `offscreen.deviceScaleFactor`), so templates see `devicePixelRatio` 1 and frames are captured at exactly the declared size on HiDPI displays. A capture at any other size now fails the render with a clear message instead of being silently resampled.
- When a template throws during a render, the error names the template, the frame, the error type and the file and line inside the template.
- The template bridge script is injected on one line so line numbers in template errors match the template's own file.

### Fixed

- The template page now says what frame it has drawn (`window.__pulp.drawn`), and the stage puts its frame state on the preview box, so a test — or a person — waits for the frame it changed rather than guessing how long a two-core machine takes. Four Windows end-to-end failures were canvases read one change too early.

- A bundled font would not load in a template page on Windows, and the frame waited for it for ever, so a line added to a template never appeared. A font load is a CORS request even to the page's own origin, and these schemes enforce CORS; the answer now says who may read it instead of relying on two custom-scheme origins comparing equal, and `font-src` names the scheme as well as `'self'`. The bridge's wait for a face is bounded at three seconds, so a font that cannot be fetched costs one frame in the fallback rather than every frame. The layers tests put the template's own layers back even when they fail, so one failure no longer wrecks the next test.

- The preview could freeze for good. A frame is drawn when the template page answers, and a page with no room on screen — the stage collapsed, squeezed to nothing, or the window too short — runs no animation frames and never answers, after which every later frame was parked behind the one in flight and the preview showed one stale picture until the app was restarted. Each request now has a four-second watchdog: the stage lets the unanswered one go and asks again, so the preview catches up by itself as soon as it has room. This is what made three Windows end-to-end tests fail on the small display the runner has.

- The stage preview could be squeezed out of shape. Its box took the full width at the picture's ratio and then had its height clamped, so while the window loaded or a region resized the box lost its shape and the template or media inside was stretched. The box is now sized from the room it has: the largest box of the picture's own ratio that fits, letterboxed or pillarboxed, and not drawn at all when there is no room — for 16:9, 9:16, 1:1 and 4:5 templates and for media alike. A UI test squeezes the stage narrow, short and a step at a time and checks the drawn ratio after every change.
- The results list kept no minimum height. On a short window — a 1024 × 768 display, or any window once the collection tray opened — the stage's share of the center column could squeeze the list to a few pixels, which is what the Windows end-to-end failures were: a list too short to scroll through, not an app that had stopped answering. The results now keep at least 160 px, the stage gives way first and clips rather than painting over them, and the tray is capped so the center column keeps room for the search bar, the results and about 180 px of stage. The UI test emulates a short window and checks all three, and its result sweeps are bounded by the list's own length instead of a fixed step count.
- A window asking about a path that does not exist (Copy path, Reveal or a drag of a file that is not the app's) left an unhandled rejection in the main process: the cache check started resolving the path before it had awaited the cache folder. It resolves the folder first now.
- The test suite can no longer stall on a child process. Every ffmpeg, ffprobe, Electron and build run the end-to-end tests start goes through one runner with no stdin, a time limit and a whole-tree kill (which Windows needs: killing Electron's main process leaves its helpers holding the pipes), ffmpeg is always started with `-nostdin`, the CI jobs have time limits, and on CI the reporter names each test as it starts, so a stall says where it is.
- The Info tab's Location row read `boardroom\lower-third` on Windows. It is a breadcrumb inside the library folder, not a path, so it now uses forward slashes on every platform; the tooltip keeps the native path.
- `settings.json` (library folders, recent colors) is written atomically: a temporary file is renamed over the old one, so a crash or a reader during a save sees the old or the new file and never a half-written one that would lose the library folder list. Changes that arrive close together are queued so none is lost.
- The end-to-end tests' cleanup no longer fails on Windows with EBUSY: they wait for the app to exit and delete scratch folders with retries, since Windows refuses to delete files a just-killed process still holds.
- The first captured frame could be blank or one frame stale on slow machines (seen on Windows CI with trimmed and flattened renders). The template bridge now resolves two animation frames after drawing, and the renderer forces a repaint and waits for the paint event before each capture, so the capture always holds the frame that was just drawn. The offscreen window's begin-frame rate is raised to 240 so the extra waits cost about 4 ms, which makes renders faster than before the fix (lower third: 67 frames/s raw against 54).
- Raw frames with ffmpeg 8.1 and later. Those versions negotiate an alpha mode on filter links and treat untagged raw input as straight alpha, so ffmpeg premultiplied the already premultiplied frames before the unpremultiply step: semi-transparent pixels came out dark (a white 85% panel read 216 instead of 255) and every color one step low. The renderer now detects alpha mode support and tags raw frames with their measured layout first. Verified with ffmpeg 8.0 and 9.0.2; found by the Windows CI job.
- Raw frames no longer depend on assumptions about the capture bitmap. The renderer measures the byte order and premultiplication of `toBitmap()` output with a probe page before the first render (Electron documents the layout as platform-dependent), passes the result to ffmpeg, and falls back to PNG frames with a warning if the bytes fit no known layout. The unpremultiply step is fed planar RGB explicitly so format negotiation cannot pick a lossy Y'CbCr intermediate.
- Cancelled or failed renders no longer leave partial output files behind. Files that existed before a render without overwrite are kept.
