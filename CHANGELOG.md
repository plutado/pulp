# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Security

- Electron 44.9.1, which carries the mitigation for compromised eMudhra intermediate certificates (GHSA-jr5w-w6x2-84p9) that 44.9.0 lacked. CI now audits dependencies and fails on a known high or critical advisory.

### Fixed

- The collection tray no longer keeps a stale message. "Every item now has those output settings.", "Saved as …" and "Rendering 3 items." used to stay on the status line after the collection was emptied, replaced or changed, describing something that was no longer there. A confirmation now fades after a few seconds and goes the moment the collection changes under it; an error waits until the next action, so it is not missed; and an empty collection says only "Nothing collected yet."

- A squeezed stage keeps its picture. With the collection tray open on a short window, the stage gave every pixel to its own transport, tools and item row and left the preview nothing: the picture went invisible under its "no room" rule and the stage could not be clicked at all. The picture now keeps a floor and the chrome around it gives way first; when even that cannot be met the stage says so instead of showing nothing, and the layer overlay stops taking clicks it could never act on. This is what had been failing on Windows CI, where the window is 1008 × 655 (docs/platform-notes.md).

- Clicking a layer on the stage selects it reliably, including on a small window. The overlay could hit-test what the preview had laid a frame ago — the page says it has drawn before it reports what it drew — so a click could land on where a layer used to be; the report now names its frame and the overlay waits for the matching one. And a hit no longer has to be pixel-exact: on a preview a few hundred pixels wide a line of type is a few pixels tall, so a click within four screen pixels of a layer takes it. Found on Windows, where the CI window previews a 1920-pixel frame about 157 px wide (docs/platform-notes.md).

- The results grid no longer leaves a band of empty space under every wide card. One square or portrait item anywhere in the results — a 512 × 512 logo was enough — used to set the row height for the whole grid, so each wide card's picture and text sat in the top half of its cell. A grid that mixes shapes now lays out at 16:9, with a taller picture contained in the same box and its Vertical badge still saying what it is; the taller pitch is kept for a set that is square or taller all through, where every card needs the height.

- The preview answers even when the window is occluded or the frame has no screen time. Chromium throttles rendering for a window it believes no one can see — a covered window, a CI runner's desktop — and `requestAnimationFrame` then never fires, so the template page could never say a frame was drawn: the frame asked for never arrived and the stage's watchdog let request after request go. The window now opts out of background throttling, and the bridge's after-draw wait of two animation frames is bounded at a quarter of a second — the draw itself has already happened when the wait starts — so a frame is declared drawn rather than held forever (docs/platform-notes.md, "A throttled renderer runs no animation frames at all").

### Changed

- No label repeats the heading it sits under. "Logo" as a card's title and "Logo" again as its one field read "Logo, Logo" over the image well; a field whose label matches its card's title — or, in a plain form, its group heading — now keeps the text as its accessible name and shows nothing. One rule in the core, in the style guide, and held to by the style test across every bundled template's Parameters tab.

- Packaging is the last step of the project: milestones 17 (unsigned builds) and 7 (signing and auto-update) move to the end of the planned order, after 1.0 hardening, in the roadmap and the README. Milestone 17 gains an app icon of Pulp's own — an original mark, exported as `.icns`, `.ico` and the PNG sizes Linux wants — with the app named "Pulp" wherever a system names it, desktop and Start menu shortcuts from the Windows installer, and a Linux desktop entry.

- The Windows CI section of `docs/platform-notes.md` is findings rather than an investigation diary: the runner and the job, the three path and line-ending failures with their one shortcut, the squeezed results list that caused the eleven UI failures, the hover-scrub fixes, and what a failing run reports now. Three claims that turned out wrong are gone — the job that printed nothing was cancelled after about fifteen minutes rather than running to six hours and was most likely slow rather than stuck, a healthy Windows run takes about 6.5 minutes, not 20 (the comment on the job's timeout says so too), and a silent Windows run is not by itself evidence of a process a test is waiting on.
- The image slot field in the Parameters tab is one pattern end to end: a well the width of the field at a fixed height, the image contained and centred on the checkerboard so a wide badge, a square mark and a tall crest all sit in the same box; under it one row with the image's name, its pixel size once the library has measured it, and Replace and Clear as icon buttons; then the treatment as a segmented control with the tint swatch beside it only for Tinted, and Shadow and Glow as toggles. The empty state is the same well, dashed, reading "Choose or drop an image" — and an image file dropped on it is imported into the Imported folder exactly as the File… button does. Checked at the default inspector width and at its narrowest, where the field holds to the panel and the treatment row wraps. Screenshot retaken.

### Added

- Typing a category in the browse panel now filters the tree itself instead of offering a list beside it (milestone 24, refined). Letter by letter, every node that no longer matches disappears; the ones that remain keep their section and their group, so it is plain where each lives, and with everything else gone they sit at the top of the panel with nothing to scroll. The matched letters are lit, every section holding a match opens for as long as the search lasts, and clearing the field puts the tree back exactly as it was, folds included. Enter takes the first category that answered — not the section or group kept above it — and "No category matches" says so when none does.
- The browse tree shows only where you are. With one section open at a time (the default), the panel opens folded to the path of the active category, or on Quick access alone when nothing is active, and choosing a category — by clicking it or through the find field — opens its path and folds everything else. With the setting off, folding stays free.

- The first assets (milestone 26). Assets are isolated elements on transparency that a person places on a frame — as distinct from an overlay, which covers the whole frame — and they have a type group of their own in the browse tree, starting with ten Effects categories: fire and flames, smoke and steam, sparks and embers, explosions and impacts, energy and magic, light and flares, weather effects, liquids and splashes, confetti and celebration, brush and ink strokes. Each begins with two generated CC0 examples, a transparent WebM and a transparent PNG, drawn on demand by the sample generator and never committed: a candle flame and a torch, smoke wisps and steam, a spark shower and drifting embers, a shockwave and a dust burst, an energy orb and a sparkle trail, a glint and a lens flare, falling rain and a snow flurry, a water splash and an ink bloom, a confetti burst and glitter, a brush swipe and a marker underline. The looping ones meet their first frame again; the one-shots play once and clear. The taxonomy version moves to 3.

- Move and resize layers on the stage (milestone 25 — the milestone is complete). Click a line or a logo in the preview and it is selected, there and in the Parameters tab at once, wearing a thin outline with corner handles. Drag it anywhere on the frame; it snaps to the frame's centre lines, the safe-area edges and its own block's edges, drawing a guide while it holds. A corner handle scales it about its centre, proportions kept; the arrow keys nudge it, a bolder step with Shift; Escape lets go. Every gesture is one undo step, "Reset position" on the layer's card puts it back where the stack places it, and the template's motion — or the layer's own override — still carries it from wherever it was put. Checked end to end at 16:9 and 9:16 with a line and a logo: dragged, snapped, nudged, resized, undone, and still absent before its entrance.
- A layer can carry a placement (milestone 25, the first item): an offset and a scale per aspect, as fractions of the frame, applied by the host around the template's own draw of that layer — so a placed layer still enters, moves and leaves with the design, templates need no changes, and a layout placed at 16:9 never moves what was placed at 9:16. It rides the same bag of values as every layer edit, so presets, collections, CSV, `--param '@layers={…}'` and the render cache key carry it already. The stage gains the handles next; until then the command line and files set it.

- Every category in the browse tree is at least six samples deep (milestone 24, the last item — the milestone is complete). Twenty-seven new original CC0 templates fill the nine types whose samples must be animations, three apiece: openers (sunrise rays, a civic seal, city windows coming on), end cards (memorial, thanksgiving, subscribe), callouts (vitals, citation, price board), social straps (a typing handle, a poll, a profile card), reveals (ink, curtain, leaves), flashes (press pit, soft bloom, floodlights), glitches (tape, hologram, signal drop), counters (donations, fitness, laps) and countdowns (launch, kitchen timer, race start). The sample-media catalogue grows to 252 files with themed sounds and motif icons — ballpark organs, gavel raps, goal horns, fireworks, thunder, church bells, and a flat emblem for every themed folder — so every theme from baseball to halloween to weather stands six deep too. The old "three to five" band is corrected everywhere it stood as a rule: it was only ever shorthand for "never one option, always several", so the floor stays and the ceiling is gone.
- The browse tree keeps one section open at a time (milestone 24). Opening a section — or a type group inside one — folds the others at its level, so a tree that now maps 46 types, 51 themes and 11 styles stays short while you move through it; folding is always free, and the tree still starts fully open. On by default; `browseAccordion: false` in settings.json folds and unfolds freely, as before. Choosing a category in the find field unfolds the path to it and moves nothing else: a find is a jump, not a reorganisation.
- Find a category as you type (milestone 24). A field at the top of the browse panel searches the tree itself: typing lists matching nodes across every taxonomy — types, themes, styles, packs, folders, and the Quick access entries — each named with the section it lives in ("Lower third · Types", "Holiday · Themes"), best answers first. Choosing one selects that node and scopes the results exactly as clicking it in the tree does, scope chip and all, and the tree unfolds to show where the choice lives. Keyboard first: the arrows move through the answers, Enter chooses, Escape clears. It finds categories; the search bar above the results keeps finding items.
- A layer can carry a motion of its own (milestone 23, the last item). The template owns how a layer arrives — that is what a block is for, and it is what lets a line added in the middle move as the middle line of the design does — but under **Advanced** on any layer's card that can now be overridden for that one layer: Fade, Slide, Scale or None, after a delay of up to ten seconds. A slide travels the layer's own size, so it reads the same on a heading and on a caption and at every resolution; a scale grows from 0.8; None is a layer that simply arrives, which a delay still holds off. Two rules keep an override inside the author's design, and a template needs no code for either: the entrance is the person's but **the exit stays the template's**, so when the graphic clears the layer goes with it and nothing can be left on screen after the design has gone; and the entrance always finishes inside the template's own time, so a delay longer than the template cannot leave a layer that never arrives. The timing is a pure module with unit tests, mirrored in the bridge as the layout already is, and the end-to-end test overrides a line, sees it drawn where the template was still holding it back, and reads the first and last frames to prove it comes and goes with the card.
- Importing your own fonts (milestone 23, decision record 0014). The family list ends with "Import font…": a TTF, OTF or WOFF2 file is read for the family it calls itself, the person writes what they know of its licence, and the file is copied into a managed fonts folder under the app's user data. The family then stands in every family list under an "Imported" divider, set in its own face with the licence note beside it, and both the app window and every template page declare its `@font-face` from that folder — the note is recorded and shown, the licence itself is the person's to answer for. An exported pack never carries an imported font: a template set in one is named in the export's result, so sharing a pack cannot redistribute someone else's licence, and whoever installs it knows what to supply. A collection card whose layers are set in a family that is nowhere on this computer says so — as does the layer's own card — rather than quietly rendering in a fallback face.
- Image layers (milestone 23). "Add layer → Image" puts a picture in the stack: the same picker, by-id grant and treatments as an image slot, plus the picture's size as a share of the frame and its alignment, and no type. It stacks with the lines and takes the movement of its position — a mark added above the title fades in with the first position while the title waits its turn — and hides, moves, removes and resets like any layer. Proved on Title Card and Lower Third Bar at 16:9 and 9:16.
- The results area says what it is when it has nothing to show. A small label names the region and counts what it holds — "Results · 0 items" — whether or not it is empty. When it is, barely-there outlines of cards fill the space in the current view and card size, a hairline each with no fill and nothing that moves, so it reads as a grid with nothing in it; over them, a centred line says why and offers the way out: no matches for a search or a chip (Clear search, Clear filters), nothing in the chosen corner of the library yet (Search the whole library), or no library at all (Add folder, Add sample media…). The outlines are decoration — out of the tab order and hidden from screen readers — and an empty region no longer scrolls.
- An image slot can be hidden, not only cleared (milestone 22). Clearing forgets the image and brings the slot's fallback text back, so there was no way to leave that spot deliberately empty. Hidden draws nothing there — no image and no fallback — keeps the chosen image for when it is shown again, and lets a design that reserves room for the slot close the space up, which the lower thirds do. An eye toggle sits beside Replace and Clear, as a layer's does; the state rides in the slot's value, so presets, collections, a CSV cell (the word "hidden"), the render cache key and undo all carry it. Templates that draw their own words where a logo would go ask `window.pulpSlotText`, which gives nothing when the slot is hidden.
- Run from source, the window names the checkout it is running from — "Pulp — feature-x" — so two copies side by side can be told apart in the Dock, the task bar and a window list. A packaged build is just "Pulp". The page's own title is unchanged.
- The Parameters tab is organised by part of the graphic, not by kind of setting (milestone 23). A flat "Colors" group stopped saying what each colour affects once the words became layers — which text is "Text color"? — so a template names the part a setting belongs to (`element`, beside `group`), and the tab is one collapsible card per part: a card for each line of type with its words, its face and its own colour and what can be done to it, a card for the panel with its fill and accent together, one for the logo's well and treatment, and "Layout and timing" last for position, timing and duration. Layers a person adds are cards like the template's own, and a card stays folded as the form is rebuilt. A template that names no element keeps the plain form it had. Title Card and Lower Third Bar are regrouped.
- Layers travel every route a parameter does (milestone 23). They ride in the same bag of raw values, so a saved preset, a collection card, a `.pulpcollection` file and the render cache key already carried them; `--param '@layers={…}'` now takes them as JSON on the command line, patching the template's stack rather than replacing it, and naming a bad block, a layer the template does not have, or unreadable JSON instead of quietly rendering the defaults. Each route has its own check: a preset file, a collection round trip and a collection render, two stacks the cache tells apart, a CSV batch, and a headless render.
- The Lower Third Bar's words are layers (milestone 23, the second proof). Its name and title are the two layers of a `strap` block; the template lays the stack out once to measure — the widest line sets the panel's width, the stack's height its height — and once more in place, aligned to the side the panel sits on, and the host draws the words inside the panel's own wipe. A third line added in the Parameters tab grows the panel upward to hold it and rides the same wipe and fade, wide and tall. With the defaults it renders exactly as it did: all 360 frames checked at 16:9 and 9:16 are byte for byte what they were. Its font and text colour are layer properties now, edited under each line; the accent and panel colours, the position, the timing and the logo slot are unchanged.
- A CSV batch column may name a text layer, by id or label, as it may a parameter: the row carries the template's stack with that layer's words changed, and is named by it when there is no name column. A collection item carries its layers the same way, in the same bag as its parameters.
- Ten bundled fonts (milestone 23, decision record 0014): Inter, Montserrat, Oswald, Bebas Neue, Source Serif 4, Playfair, JetBrains Mono, Caveat, Dancing Script and Noto Sans, each taken from its upstream with its own licence file and confirmed from that file to be under the SIL Open Font License 1.1. The two that declare a Reserved Font Name (Source, Dancing Script) ship as the upstream bytes untouched, and a test holds every file to its hash. `docs/font-credits.md` names family, version, licence and source. Template pages get the fonts under their own origin at `/__pulp/fonts/`, which their Content Security Policy already allows, with an `@font-face` per file declared by the bridge; the bridge loads a layer's face before the frame that draws it. Playfair stands where the roadmap said Playfair Display: that family's upstream is now the Playfair superfamily, whose display cut is the large end of its optical-size axis.
- Text layer properties in the Parameters tab (milestone 23). Each text layer's words carry a folded line beneath them — "Georgia · 8.9% · Regular · Uppercase" — that opens to its type: family, size as a percentage of the frame, weight, italic, case, letter spacing in em, kerning, line height, space before, colour, alignment and overflow, with the line limit for wrapped text. The family control lists the bundled ten and then the template's own stacks, each set in its own face. Every change is one undo step. The Title Card's font and text colour, which became layer properties when its words became layers, have their controls back here.
- Layers in the Parameters tab (milestone 23). A template that declares blocks gets a Layers section: the stack as it is drawn, each layer with its words, a hide toggle (kept but not drawn, the stack closing up), Move up and Move down, and Remove unless the template marks the layer required. "Add layer" offers Text or Image, and "Reset layers" puts the template's own back. Every change is one undo step with the parameters, because the stacks ride in the same bag of values — which also means they travel with a collection card, a saved preset and a render without a second channel.
- The Title Card's words are layers. Its title and subtitle are the two layers of a `card` block: the host measures, wraps and stacks them, and the template keeps its own motion — each line fades in 0.7 s after the one above it, the first tracks out wide and settles, the rule follows the first line and a logo still sits above it. A third line added in the Parameters tab rides the same fade in its turn, wide or tall. With the defaults the card renders as it did: of 300 frames checked at 16:9 and 9:16, 289 are byte for byte what they were, and the 11 that differ are the tall card's first third of a second, where the title is set a little smaller to fit while it is tracked out — letter spacing is type now, so it scales when the type does. Its font and text colour moved onto the layers with the words, and the controls for them arrive with the next item; its background and rule colours and its logo slot are unchanged.
- Blocks draw (milestone 23). `state.blocks` carries each block laid out for the frame — its box in pixels and the layers that are drawn, in stack order, hidden ones left out so the stack closes up — and the bridge finishes it: `window.pulpLayoutBlock` measures the text, wraps it, sets it smaller or cuts it with an ellipsis as the layer asks, stacks the layers with their gaps and places the stack in the box, and `window.pulpDrawBlock` draws the result. A per-layer hook is called with the layer's **stack position**, and what it returns — alpha, an offset, a scale, the letter spacing to measure with — rides that position, so a line added in the middle takes the movement of the middle. A text layer may say how many lines it may take (`maxLines`) before it is set smaller. The arithmetic is a unit-tested core module that the bridge mirrors.
- Blocks and layers in the template format (milestone 23, the first item). A template can declare `blocks`: a box per aspect (as an image slot's), a stacking direction and gap, an alignment, whether the block is open to more layers, the typography its text layers start from, and its own layers — text layers with a default text and any of family, size (a fraction of the frame's short side), weight, italic, case, letter spacing, kerning, line height, colour, alignment and overflow; image layers with a size and an alignment and no image of their own; either kind optionally required or hidden. The validator checks all of it with paths and fills every default, and a pure module resolves what a person builds at use time against the template's own stacks: wrong fields fall back and are reported, type and required never change, a dropped required layer comes back in its place, and additions to a full block are dropped. Nothing is drawn from blocks yet; the state and the bridge helper are the next items.
- A "logo reveal" type in Titles and text (taxonomy version 2; the list only grows). Three standalone reveals built around a logo slot — Minimal (a fade-up over a hairline), Line-drawn (a frame draws itself around the mark) and Light sweep (a band of light crosses it) — and a short ident for each matched set, one to three seconds on a dark ground with one move in the set's look. With no logo chosen each is a wordmark reveal of the name set in type. The browse tree's Titles and text group gains the type; the coverage rule lets this one type run to seven, since three families plus four idents is what it takes.
- The image slot field in the Parameters tab shows the chosen still at the slot's own shape, filling the field's width up to a sensible height, with the image's name beneath and the buttons below; the empty state is the same box, a dashed place to choose from. The preview comes from the still itself until the library has a poster for it, so it is never a broken image.

- Logo slots across the sample sets, 26 in all: a badge at the head of each set's lower third, a mark above each title, a logo in each corner bug, a logo at the centre of each transition while it covers the frame, a lockup on each end card (the opener, for Matchday), a watermark on each background, and a mark above Title Card. Every one falls back to the piece's own text or to nothing, so with no logo chosen every template renders byte for byte as before.

- A chosen logo travels everywhere a parameter does: through the render queue, Prepare for drag, collection cards and `.pulpcollection` files, and headless `--param slot=<id>`. A CSV batch column named after an image slot picks a logo per row, by library id or by a file name looked up in the Imported folder; a row whose logo cannot be found is named and skipped rather than rendered blank. The render cache keys on the image's id, size and modification time, so a replaced logo renders afresh. A chosen image that has left the library, or whose folder is offline, is flagged on the collection card, in the Parameters tab and in the Info tab, and a render refuses it with the reason.
- A diagnostics call for the background queue: what is being thumbnailed or probed, how much is waiting, and which heavy job is running and for how long. The end-to-end UI test prints it, with the window's visibility and the main process's last lines, whenever a test fails.

- Image slots in templates. A template can declare an `image` parameter: a box in its layout — as fractions of the frame, per aspect where it needs to — with a fit, an alignment, a safe margin and a text fallback, and draw the chosen still inside its own animated layers with one call, so a logo follows every move the graphic makes. The Parameters tab gets a picker with a thumbnail: a still from the library (with search) or a file, which is copied into a managed Imported folder and indexed; Clear; a note when the chosen image has gone or its folder is offline. Treatments ride with the choice — original colours, tinted, white or black, with an optional shadow or glow — and saved presets remember the choice by library id. Images are decoded before the first frame, so no frame is drawn with a half-loaded logo. Lower Third Bar gains a logo badge at the head of its panel that falls back to the name; with no logo it renders exactly as before.
- Templates see only the images chosen for them (decision record 0013). The main process reads exactly the stills picked for a template's image slots, by library id, and hands the page their bytes for as long as the preview shows them or a render runs; the media handler still refuses every request from a template page, and the template never holds a way to ask for anything else. SVG logos are rasterised through an image element, which runs no script and loads nothing external; files over 64 MB are refused, and decoded bitmaps are capped at 4096 px on the long side.

- Every bundled template now draws for all four shapes. The originals that were written for 1920 × 1080 declare the aspects instead, and each set's lower third and title re-lay out for a tall frame: the lower third sits above the caption band and clear of the controls column, the title wraps and centres above the middle. The same template is its own vertical version; its 16:9 output is unchanged.

- Cards take the item's own shape. A portrait clip or a square still is drawn tall or square on its card instead of being letterboxed into a 16:9 box; a grid holding one takes a taller row for all its cards so the pitch stays even, and an all-landscape grid looks exactly as before. The Info tab's poster follows.

- Vertical safe zones. With the safe areas on and a tall frame in the preview, the stage also marks the areas a vertical video has to keep clear — a header strip at the top, a controls column down the right, a caption band across the bottom — described generically so they hold for any platform.

- Orientation in search and on cards: `orientation:portrait` (or `vertical`), `landscape` and `square` filter templates by the shapes they draw for and media by its size; a Vertical chip sits beside the media kinds; and portrait and square items carry a badge, so a tall item is recognizable without reading its size.

- The Output tab chooses the shape and size of a render. Templates that draw for more than one aspect get an Aspect field; every template gets a Resolution field with its own size or the aspect's default, the standard sizes for that aspect, and a custom width and height that must be of the aspect. The preview turns to match, so a tall render is previewed tall, and a collection card remembers the choice like its other settings.

- Thirty more original CC0 sample templates complete the sample library: every one of the 45 types now has three to five examples across the templates and the sample media. Backgrounds: Boardroom paper, Cinematic gradient and Soft gradient (still backgrounds), Film grain field, Halftone dots and Scanlines (textures). Transitions: Boardroom blinds, Festival iris matte and Matchday split (reveals), Festival sparkle flash, Newsdesk flash cut and Cinematic light flash, Newsdesk glitch, Tech glitch and VHS glitch. Overlays: Boardroom dot grid, Newsdesk ticker, Matchday chevron band and Festival ribbon, Festival and Matchday frames, Festival confetti burst and Dust motes, Film grain, Scratches and VHS tracking, a Boardroom bug, and Soft, Letterbox and Retro vignettes. The sets are now thirteen to fifteen pieces each in one look, and the styles list covers all eleven styles but corporate.

- Sample media on demand. "Add sample media…" in the browse panel (and `--sample-media <folder>` headlessly) makes a "Sample media" folder of original CC0 files — synthesized whooshes, impacts, beeps, alarms, ambiences, weather, animal calls, vehicles, crowds, foley, explosions, sci-fi sounds and musical phrases; three short synthesized pieces with one of them as stems, and three stings; photo-style, illustrated and layered stills drawn on a canvas; and the four background templates as short clips — in folders whose names give each file its type, so every media type in the browse tree has three to five examples. Files that already exist are left alone, so the folder can be topped up. Nothing is recorded and no binary file ships with the app; a README in the folder says how each file was made.

- Thirty more original CC0 sample templates, so every type under Titles and text and Design elements has at least three. The four matched sets each gained pieces in their own look: Boardroom an opener, rolling credits, a callout, an arrow, a bar chart and a counter; Newsdesk an opener, an end card, a quote caption, a social strip, a pointer and a poll; Matchday an opener, a follow chip, a head-to-head, a match clock and a kick-off countdown; Festival an end card, a speech-bubble callout, a subscribe pill and a midnight countdown. Standalone templates fill out the styles list: Tech hex burst, Retro sun stripes and Soft blobs (shapes), Line icons, Hand-drawn icons and Playful icons, Hand-drawn arrow, Elegant counter and Cinematic leader. All of them declare the four aspects and lay out from the frame they are given.

- Templates are shapes, not pixel sizes. A manifest now declares the aspect ratios it draws for (`aspects`: 16:9, 9:16, 1:1, 4:5) and the output size is chosen when it is rendered, from a standard list per aspect or as an exact size; headless renders take `--aspect` and `--size`. The renderer sizes its window, checks its captures and feeds ffmpeg from that choice, and thumbnails and hover-scrub strips follow the template's default. Manifests written with `width` and `height` keep working: the aspect is inferred and the size becomes that template's default resolution. The Info tab lists a template's aspects and says when its size is chosen at render time. The format spec and decision record 0012 describe the change. The Output tab's aspect and resolution controls follow.

- Audio files show their shape: a waveform fills the stage behind the transport and sits in each list row where a thumbnail would be. The peaks are read once with ffmpeg and kept with the library, so a folder of sound effects is legible at a glance and stays that way without re-reading the files.
- Audition mode, for working through a folder of sounds: turn it on in the preview tools and Up and Down walk the results playing each one as it comes up, with Escape to stop. The arrow keys move through the results whether or not it is on.
- The player grew up: a loop toggle (with it off, playback stops on the last frame instead of starting over), frame-step buttons both ways, and Set in / Set out, which mark the render's trim from the playhead and draw it on the scrub bar with the dropped ends dimmed. The marks and the Output tab's in and out points are the same thing now — set either and both follow. Volume and mute sit next to them and are remembered, including when you change them on the video's own controls.
- The preview background is yours to choose: checkerboard, black, white or any colour, instead of the checkerboard appearing only for templates that declare alpha. A toggle draws the title-safe and action-safe rectangles over the frame. Both are remembered in `settings.json`.
- Hover-scrub: resting the pointer on a card and moving across it steps through eight frames of the item, so a transition or a clip can be read without playing it. ### Changed

- QuickTime Animation output carries a `colr` atom declaring full-range RGB (GBR matrix, BT.709 primaries and transfer); MOV has no range flag for RGB codecs, and without the atom Resolve's Data Levels Auto treated the file as video range and scaled the alpha. PNG sequences carry the same frame tags, which PNG ignores.
- Video presets (ProRes 4444, ProRes 422 HQ, H.264, VP9) now convert to Rec.709 with the BT.709 matrix at limited range and tag the output BT.709 primaries, transfer and matrix, limited range. Before, files carried no color information and ffmpeg used its BT.601 default, which shifted saturated colors in editors. Alpha templates are composited over the background in RGB before the conversion. PNG sequences stay full-range sRGB. Decision record 0004 has the reasoning, including why the transfer is tagged BT.709 rather than sRGB.
- Frames travel to ffmpeg as raw BGRA pixels instead of PNG images, removing a PNG encode in the app and a decode in ffmpeg per frame. Frames from alpha templates are unpremultiplied in ffmpeg, so semi-transparent edges keep their color. `--frame-format png` keeps the old path for comparison, and headless mode prints elapsed time and frames per second. Measurements are in `docs/system-design.md`; the reasoning is in decision record 0003.
- The offscreen render window is created at device scale factor 1 on purpose (Electron's `offscreen.deviceScaleFactor`), so templates see `devicePixelRatio` 1 and frames are captured at exactly the declared size on HiDPI displays. A capture at any other size now fails the render with a clear message instead of being silently resampled.
- When a template throws during a render, the error names the template, the frame, the error type and the file and line inside the template.
- The template bridge script is injected on one line so line numbers in template errors match the template's own file.

### Fixed

- The template page now says what frame it has drawn (`window.__pulp.drawn`), and the stage puts its frame state on the preview box, so a test — or a person — waits for the frame it changed rather than guessing how long a two-core machine takes. Four Windows end-to-end failures were canvases read one change too early.

- A bundled font would not load in a template page on Windows, and the frame waited for it for ever, so a line added to a template never appeared. A font load is a CORS request even to the page's own origin, and these schemes enforce CORS; the answer now says who may read it instead of relying on two custom-scheme origins comparing equal, and `font-src` names the scheme as well as `'self'`. The bridge's wait for a face is bounded at three seconds, so a font that cannot be fetched costs one frame in the fallback rather than every frame. The layers tests put the template's own layers back even when they fail, so one failure no longer wrecks the next test.

- The preview could freeze for good. A frame is drawn when the template page answers, and a page with no room on screen — the stage collapsed, squeezed to nothing, or the window too short — runs no animation frames and never answers, after which every later frame was parked behind the one in flight and the preview showed one stale picture until the app was restarted. Each request now has a four-second watchdog: the stage lets the unanswered one go and asks again, so the preview catches up by itself as soon as it has room. This is what made three Windows end-to-end tests fail on the small display the runner has.

- The stage preview could be squeezed out of shape. Its box took the full width at the picture's ratio and then had its height clamped, so while the window loaded or a region resized the box lost its shape and the template or media inside was stretched. The box is now sized from the room it has: the largest box of the picture's own ratio that fits, letterboxed or pillarboxed, and not drawn at all when there is no room — for 16:9, 9:16, 1:1 and 4:5 templates and for media alike. A UI test squeezes the stage narrow, short and a step at a time and checks the drawn ratio after every change.
- The results list kept no minimum height. On a short window — a 1024 × 768 display, or any window once the collection tray opened — the stage's share of the center column could squeeze the list to a few pixels, which is what the Windows end-to-end failures were: a list too short to scroll through, not an app that had stopped answering. The results now keep at least 160 px, the stage gives way first and clips rather than painting over them, and the tray is capped so the center column keeps room for the search bar, the results and about 180 px of stage. The UI test emulates a short window and checks all three, and its result sweeps are bounded by the list's own length instead of a fixed step count.
- A window asking about a path that does not exist (Copy path, Reveal or a drag of a file that is not the app's) left an unhandled rejection in the main process: the cache check started resolving the path before it had awaited the cache folder. It resolves the folder first now.
- The test suite can no longer stall on a child process. Every ffmpeg, ffprobe, Electron and build run the end-to-end tests start goes through one runner with no stdin, a time limit and a whole-tree kill (which Windows needs: killing Electron's main process leaves its helpers holding the pipes), ffmpeg is always started with `-nostdin`, the CI jobs have time limits, and on CI the reporter names each test as it starts, so a stall says where it is.
- The Info tab's Location row read `boardroom\lower-third` on Windows. It is a breadcrumb inside the library folder, not a path, so it now uses forward slashes on every platform; the tooltip keeps the native path.
- `settings.json` (library folders, recent colors) is written atomically: a temporary file is renamed over the old one, so a crash or a reader during a save sees the old or the new file and never a half-written one that would lose the library folder list. Changes that arrive close together are queued so none is lost.
- The end-to-end tests' cleanup no longer fails on Windows with EBUSY: they wait for the app to exit and delete scratch folders with retries, since Windows refuses to delete files a just-killed process still holds.
- The first captured frame could be blank or one frame stale on slow machines (seen on Windows CI with trimmed and flattened renders). The template bridge now resolves two animation frames after drawing, and the renderer forces a repaint and waits for the paint event before each capture, so the capture always holds the frame that was just drawn. The offscreen window's begin-frame rate is raised to 240 so the extra waits cost about 4 ms, which makes renders faster than before the fix (lower third: 67 frames/s raw against 54).
- Raw frames with ffmpeg 8.1 and later. Those versions negotiate an alpha mode on filter links and treat untagged raw input as straight alpha, so ffmpeg premultiplied the already premultiplied frames before the unpremultiply step: semi-transparent pixels came out dark (a white 85% panel read 216 instead of 255) and every color one step low. The renderer now detects alpha mode support and tags raw frames with their measured layout first. Verified with ffmpeg 8.0 and 9.0.2; found by the Windows CI job.
- Raw frames no longer depend on assumptions about the capture bitmap. The renderer measures the byte order and premultiplication of `toBitmap()` output with a probe page before the first render (Electron documents the layout as platform-dependent), passes the result to ffmpeg, and falls back to PNG frames with a warning if the bytes fit no known layout. The unpremultiply step is fed planar RGB explicitly so format negotiation cannot pick a lossy Y'CbCr intermediate.
- Cancelled or failed renders no longer leave partial output files behind. Files that existed before a render without overwrite are kept.
