# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Image slots in templates. A template can declare an `image` parameter: a box in its layout — as fractions of the frame, per aspect where it needs to — with a fit, an alignment, a safe margin and a text fallback, and draw the chosen still inside its own animated layers with one call, so a logo follows every move the graphic makes. The Parameters tab gets a picker with a thumbnail: a still from the library (with search) or a file, which is copied into a managed Imported folder and indexed; Clear; a note when the chosen image has gone or its folder is offline. Treatments ride with the choice — original colours, tinted, white or black, with an optional shadow or glow — and saved presets remember the choice by library id. Images are decoded before the first frame, so no frame is drawn with a half-loaded logo. Lower Third Bar gains a logo badge at the head of its panel that falls back to the name; with no logo it renders exactly as before.
- Templates see only the images chosen for them (decision record 0013). The main process reads exactly the stills picked for a template's image slots, by library id, and hands the page their bytes for as long as the preview shows them or a render runs; the media handler still refuses every request from a template page, and the template never holds a way to ask for anything else. SVG logos are rasterised through an image element, which runs no script and loads nothing external; files over 64 MB are refused, and decoded bitmaps are capped at 4096 px on the long side.

- Every bundled template now draws for all four shapes. The originals that were written for 1920 × 1080 declare the aspects instead, and each set's lower third and title re-lay out for a tall frame: the lower third sits above the caption band and clear of the controls column, the title wraps and centres above the middle. The same template is its own vertical version; its 16:9 output is unchanged.

- Cards take the item's own shape. A portrait clip or a square still is drawn tall or square on its card instead of being letterboxed into a 16:9 box; a grid holding one takes a taller row for all its cards so the pitch stays even, and an all-landscape grid looks exactly as before. The Info tab's poster follows.

- Vertical safe zones. With the safe areas on and a tall frame in the preview, the stage also marks the areas a vertical video has to keep clear — a header strip at the top, a controls column down the right, a caption band across the bottom — described generically so they hold for any platform.

- Orientation in search and on cards: `orientation:portrait` (or `vertical`), `landscape` and `square` filter templates by the shapes they draw for and media by its size; a Vertical chip sits beside the media kinds; and portrait and square items carry a badge, so a tall item is recognizable without reading its size.

- The Output tab chooses the shape and size of a render. Templates that draw for more than one aspect get an Aspect field; every template gets a Resolution field with its own size or the aspect's default, the standard sizes for that aspect, and a custom width and height that must be of the aspect. The preview turns to match, so a tall render is previewed tall, and a collection card remembers the choice like its other settings.

- Thirty more original CC0 sample templates complete the sample library: every one of the 45 types now has three to five examples across the templates and the sample media. Backgrounds: Boardroom paper, Cinematic gradient and Soft gradient (still backgrounds), Film grain field, Halftone dots and Scanlines (textures). Transitions: Boardroom blinds, Festival iris matte and Matchday split (reveals), Festival sparkle flash, Newsdesk flash cut and Cinematic light flash, Newsdesk glitch, Tech glitch and VHS glitch. Overlays: Boardroom dot grid, Newsdesk ticker, Matchday chevron band and Festival ribbon, Festival and Matchday frames, Festival confetti burst and Dust motes, Film grain, Scratches and VHS tracking, a Boardroom bug, and Soft, Letterbox and Retro vignettes. The sets are now thirteen to fifteen pieces each in one look, and the styles list covers all eleven styles but corporate.

- Sample media on demand. "Add sample media…" in the browse panel (and `--sample-media <folder>` headlessly) makes a "Sample media" folder of original CC0 files — synthesized whooshes, impacts, beeps, alarms, ambiences, weather, animal calls, vehicles, crowds, foley, explosions, sci-fi sounds and musical phrases; three short synthesized pieces with one of them as stems, and three stings; photo-style, illustrated and layered stills drawn on a canvas; and the four background templates as short clips — in folders whose names give each file its type, so every media type in the browse tree has three to five examples. Files that already exist are left alone, so the folder can be topped up. Nothing is recorded and no binary file ships with the app; a README in the folder says how each file was made.

- Thirty more original CC0 sample templates, so every type under Titles and text and Design elements has at least three. The four matched sets each gained pieces in their own look: Boardroom an opener, rolling credits, a callout, an arrow, a bar chart and a counter; Newsdesk an opener, an end card, a quote caption, a social strip, a pointer and a poll; Matchday an opener, a follow chip, a head-to-head, a match clock and a kick-off countdown; Festival an end card, a speech-bubble callout, a subscribe pill and a midnight countdown. Standalone templates fill out the styles list: Tech hex burst, Retro sun stripes and Soft blobs (shapes), Line icons, Hand-drawn icons and Playful icons, Hand-drawn arrow, Elegant counter and Cinematic leader. All of them declare the four aspects and lay out from the frame they are given.

- Templates are shapes, not pixel sizes. A manifest now declares the aspect ratios it draws for (`aspects`: 16:9, 9:16, 1:1, 4:5) and the output size is chosen when it is rendered, from a standard list per aspect or as an exact size; headless renders take `--aspect` and `--size`. The renderer sizes its window, checks its captures and feeds ffmpeg from that choice, and thumbnails and hover-scrub strips follow the template's default. Manifests written with `width` and `height` keep working: the aspect is inferred and the size becomes that template's default resolution. The Info tab lists a template's aspects and says when its size is chosen at render time. The format spec and decision record 0012 describe the change. The Output tab's aspect and resolution controls follow.

- Audio files show their shape: a waveform fills the stage behind the transport and sits in each list row where a thumbnail would be. The peaks are read once with ffmpeg and kept with the library, so a folder of sound effects is legible at a glance and stays that way without re-reading the files.
- Audition mode, for working through a folder of sounds: turn it on in the preview tools and Up and Down walk the results playing each one as it comes up, with Escape to stop. The arrow keys move through the results whether or not it is on.
- The player grew up: a loop toggle (with it off, playback stops on the last frame instead of starting over), frame-step buttons both ways, and Set in / Set out, which mark the render's trim from the playhead and draw it on the scrub bar with the dropped ends dimmed. The marks and the Output tab's in and out points are the same thing now — set either and both follow. Volume and mute sit next to them and are remembered, including when you change them on the video's own controls.
- The preview background is yours to choose: checkerboard, black, white or any colour, instead of the checkerboard appearing only for templates that declare alpha. A toggle draws the title-safe and action-safe rectangles over the frame. Both are remembered in `settings.json`.
- Hover-scrub: resting the pointer on a card and moving across it steps through eight frames of the item, so a transition or a clip can be read without playing it. The frames are made the first time a card is pointed at — rendered through one offscreen window for a template, pulled by ffmpeg for a video — tiled into one small image and cached beside the thumbnails, so it costs nothing the next time and nothing at all for the items you never look at. Stills and audio have nothing to step through and are left alone.
- The results show every match, however many: only the cards and rows in view are built, so a library of thousands scrolls smoothly in both views and the old 500-item limit is gone. Scrolling keeps the thumbnails that are already loaded, a new search returns to the top, and a rescan or a thumbnail arriving in the background leaves the view where it is.
- The results are a grid of cards: a thumbnail, the name, and badges for alpha, loop, duration, resolution and the pack an item came from — the first three as small icons with tooltips, the rest as short text ("6 s", "1080p", the long form in the tooltip). "Loop" reads the taxonomy, so an animated loop badges as one whether it is a template or a media file typed from its folder. The search bar gained a grid/list toggle and a four-step thumbnail size; list view keeps columns for name, duration, type, themes and file. Visual results open as a grid and audio-only results as a list, each remembering its own toggle in `settings.json`. What a card leaves out — the full meta line and the tags — is in the tooltip on its name, and the probed details stay in the Info tab.

- Four matched sample sets, each an original CC0 pack of five templates sharing one look (a lower third, a title, a transition, an overlay and a background). **Matchday** is the sports set: volt yellow on black, forward chevrons everywhere, chunky capitals with snappy overshoot moves, a chevron-toothed wipe, and a corner score bug with two sides and scores. **Festival** is the celebration set for any season: warm gold on deep plum, rounded pills and serif italics, confetti and twinkling bokeh, an iris wipe with a gold rim, and a hearth-lit looping background — festive without naming a holiday (the taxonomy gained a general "holiday" theme for exactly this). **Boardroom** is the corporate set: ink blue and paper white, hairline rules that draw themselves in, a steel accent, generous air and measured motion. **Newsdesk** is the broadcast set: signal red on deep navy, bold spaced capitals, a diagonal slash that runs through every piece, hard fast moves, and extras like a pulsing live flag and a corner bug. Both declare their theme and style once in `pack.json` and their templates inherit them.
- Packs can give their templates defaults: `pack.json` may declare a `type`, `themes` and `styles` that fill in whatever a template did not declare itself (its own type wins; themes and styles are added to its own). Templates remember the pack they came from, `pack:` finds them in search, and the browse tree gained a Packs section.
- The browse panel is a tree: Quick access (Favorites, Recently used), Types grouped the way the taxonomy groups them with an always-present Untyped node for what has no type, Themes in their groups plus a Custom group for your own, Styles, and Folders, every node with a count of what it holds. Counts follow what you typed and the chips you pressed, not the selected node, so picking one never empties the others; nodes the library has nothing for stay out of the way. Headings fold; arrow keys move through the tree and Enter selects.
- Search filters for the taxonomy: `type:` now also takes a type or a type group (`type:glitch`, `type:transitions`, `type:sfx`) while still meaning the media kinds (`type:audio`), `theme:` matches built-in, folder or custom themes (`theme:news`, `theme:"my show"`), and `style:` matches a template's declared styles; they combine with every existing filter, and free text finds types and themes too. The filter chips stay as decided — media kinds, alpha, favorites — the taxonomy's own vocabulary lives in the search syntax and, next, the browse tree.
- Media files are typed from their folders: a `.wav` under `sfx/whoosh/` is a Whoosh, `Music/Stings` makes a Sting, `Backgrounds/loop.mov` is an animated loop and `Backgrounds/paper.png` a still background, `Overlays/Light leaks/` light and particles, `Textures/` a texture, `Transitions/` a wipe — video can be a background, overlay, transition, title or element, and images backgrounds, textures, frames or icons, not only footage and photos. Folders that name built-in themes (`Sports/Hockey`) attach them; type ids, display labels, singular and plural forms and common editor words (light leaks, b-roll, stingers, lower thirds, logo bugs) all work as folder names, and a file in no such folder simply has no type. The Info tab grew a themes row next to the tags: folder and manifest themes stay, your own (built-in or custom words) can be added and removed, and they are kept in the library database with your tags, surviving folders going offline.
- Icons throughout, from Phosphor (MIT; decision record 0011): the browse panel's nodes and tools, the search field, sort and filter chips, the inspector tabs, play/pause, favorite as an outline or filled star, type and kind icons as thumbnail placeholders, the tray and the status bar (ffmpeg found or missing, cache, a spinner while scanning or rendering). Icon-only buttons have accessible names and show a tooltip on hover and on keyboard focus. Collapsing the browse panel leaves an icon rail you can still browse from.

### Added

- Collections. Gather items while browsing — Add to collection under the preview, or drag a card from the results into the tray — and each one keeps its own output settings: preset, frame rate, trim, and a template's parameters. Choosing a card in the tray hands it to the Parameters and Output tabs, so an item is edited with the same controls as anything else and every change goes back to the card. Reorder with the arrows, remove, or give every item the settings of the one you are editing with Apply to all.
- Save a collection as a file and open it again. It records each item by its place in your library and, for a template, by the template's own id, so a collection still finds its items after a rescan and a template still resolves in a library built somewhere else. Anything it can no longer find is flagged on the card and counted when you open it, rather than quietly dropped — which makes a saved collection a record of what a project used, not only a to-do list.
- Render all: one folder, chosen once, then every item rendered with its own settings, with progress on each card and overall in the tray. Items that cannot render — a template that has gone, a folder that is offline, or media, whose conversion comes later — are named and skipped, and the rest still renders. Finished items become the cards you drag into your editor.
- Headless `--collection <file> --out <folder>` renders a saved collection without opening the window, for scripted or scheduled work.

### Changed

- Pulp targets Premiere Pro and DaVinci Resolve on macOS and Windows. Final Cut Pro is not a target, like other editors Pulp does not verify against, and is no longer named in the preset descriptions, the verification checklist, the goals or the roadmap.
- The Info tab is a property panel. A header card — the item's picture, which scrubs when you point at it and shows a waveform for a sound, its name, its type with that type's icon, and the favorite star beside the name — over collapsible sections that remember whether you left them open: About, Format, Categories, Tags, Set, File, Credits and license, Usage. Inside each, one fact per row in a key-value grid.
- Things the Info tab never showed before: the aspect and exact duration, frame rate, codec and audio details, whether a media file's type came from its folder, the styles a template declares, the other pieces of the set it belongs to (as thumbnails you can click), where it lives, its size on disk and when it changed, its author, version and licence as a badge — in the warning colour when the licence is unknown or not an open one — and how it has been used: last used, how many times it has been rendered, and how many saved presets it has.
- Reveal in Finder (Show in Explorer) and Copy path for the item itself, not just for a render. The window asks by item id and the main process looks the path up, so no path crosses from the window and there is nothing to allow-list.
- Tags and themes gained their add control at the end of their own chip row, instead of two unlabelled fields below, and say "No tags yet" when there are none.

- The render tray was redesigned. Each render is a card: a thumbnail, the item's name, the output preset as a badge, and one line saying where it has got to — queued, a progress bar, done, or why it failed. A finished card is itself what you drag into your editor, with a grip and a hint that appears when you point at it or tab to it, instead of a card plus a separate dashed box that did the dragging. No file paths or file names in the card: the path is in its tooltip and behind Reveal in Finder (Show in Explorer on Windows), Copy path and Remove, which also give a keyboard a route to the file, since dragging needs a pointer. "Prepare for drag" is now an action next to Render on the item you are looking at, and leaves a card ready whether it had to render or found the render already in the cache. The paragraph about editors linking to files became an info icon with a tooltip, plus a notice shown once, the first time you actually drag something out.

- The browse tree no longer repeats a group inside itself. "Sports › Sports (general)" and "Holidays and seasons › Holiday (general)" are gone: where the vocabulary has a word for a whole subject, items carrying it now sit on the group's own row, and the rows beneath are the specific ones. Selecting a group finds everything in it — its own items and all its children — so `theme:sports` means every sporting item, the way `type:transitions` already meant a whole type group, and a group's count is of items, so something tagged both football and soccer counts once. The theme ids are unchanged, so nothing you have tagged moves.
- The bundled sample sets carry the specific themes they suit, so the tree shows a real hierarchy out of the box: Boardroom under corporate, finance, technology and real estate; Newsdesk under news, documentary and podcast; Matchday under football, basketball and soccer as well as sport in general; Festival under New Year, Christmas and Valentine's Day, and under birthday, graduation and wedding, since it is a set for any celebration.

- A card that was told "not ready" when it asked for its hover-scrub frames now asks again instead of giving up for the session — a clip waiting to be probed, or a busy machine, no longer leaves a card that can never scrub. Each card also keeps its own request, so moving the pointer across a row does not cancel the one you settled on.
- Internal: a hover-scrub strip that cannot be made now says why. The reason is logged and carried back to the window, and a strip that only ran out of time on a busy machine is no longer written off for good. Offscreen renders take turns, so building thumbnails for a whole library and scrubbing a card no longer fight for the same machine. The end-to-end test reports the reason instead of timing out, which is what the Windows runner needed.
- The browse tree reads as a hierarchy instead of as three font sizes: every row is at the body size, and depth is shown by structure. Sections (Quick access, Types, Themes, Styles, Packs, Folders) are small muted headings over a thin rule and are no longer rows you can hover or select; rows that hold children carry a disclosure twisty in a gutter before their icon, so icons line up whether a row folds or not; children indent one step behind a guide line, drop the group's icon and sit a shade quieter until hovered. Selection highlights the whole width of a row and marks it with an accent edge. Left now folds an open row or steps out to its parent, Right unfolds or steps in. The rules are written down in the style guide.
- The search field says "Search the library" and keeps the filter syntax in a tooltip, which the toolbar's new controls had squeezed out of the placeholder; the tooltip gets out of the way as soon as you type.
- Internal: the first DOM-level component test. The windowed results region is mounted under happy-dom (`tests/dom/results.test.ts`) and checked against scroll positions — what is built, what the spacers measure, and that an item staying in view keeps its element. Decision record 0009 deferred these until a region earned one; every other region is still covered by the end-to-end test alone.
- Library folders in the browse panel and the scope chip show humanized names ("media-library" → "Media library"; a folder already named readably stays as it is), with the full path in the tooltip.
- The last ALL CAPS headings ("LIBRARY", "PARAMETERS") are sentence-case region titles; the status bar says "FFmpeg 8.0" and the cache limit reads "2 GB" instead of "2048 MB"; the remaining three-dot ellipses became the real character. Type sizes, spacing, radii and one visible focus ring now come from design tokens, and a style test keeps it that way (no caps, no stray font sizes, no icon-only button without a name, no raw ids in label tables).
- Labels are human-readable everywhere a stored value used to show: "Lower third · 6 s · 1920 × 1080 · Alpha" instead of "lower-third · 6s · 1920x1080 · alpha", "Video · MOV · 12 MB · H.264" for media, tags and themes shown as words ("Lower third", "My show") while search keeps the stored ids, and the bundled samples' folder is "Built-in templates" in the browse panel. Render… uses a real ellipsis.

### Added

- Template manifests may declare a `type` from the built-in list, `themes` (built-in or your own, normalized like tags) and `styles` (built-in only); all three are optional and validated, `category` keeps working and maps onto a type, so existing templates are untouched. Documented in the template format specification.
- The built-in taxonomy (decision record 0010): types on two levels (nine groups, 45 types), themes (eight groups, 51 built in, extendable with your own), and styles (eleven), in a pure, versioned core module. Nothing uses it yet; the template format, media typing and the browse tree pick it up next.

- The search bar grew up: the browse panel lists Favorites, Recently used and each library folder, and selecting one scopes the results and the search to it, shown as a chip ("in: media-library") with × to widen again; filter chips for templates, video, images, audio, alpha and favorites; sorting by relevance, name, recently used or duration; and the last eight searches you pressed Enter on are remembered in `settings.json` and offered as suggestions in the search field.
- The status bar now shows the render cache size, "Scanning…" while the library rescans, and "Rendering…" with the queued count while renders run, next to the ffmpeg line and the library counts.

### Changed

- Internal: every window region is now its own module rendering from the shared state (the queue is a keyed component, so a progress tick no longer rebuilds the list and finished rows keep their drag handles), completing the milestone 11 shell. No visible change; the whole test suite, including the end-to-end UI test, passed unchanged through the move.
- Selecting a template shows the frame at mid-progress, the same frame its thumbnail uses, instead of the first frame, which is blank for transitions; the scrubber starts there and playing or scrubbing works as before.
- Default pane widths: the inspector opens at 350 px so the saved-preset row has room (the preset list now sits on its own line above the name and buttons), and the browse panel opens at 220 px until milestone 10 fills it with the browse tree. Saved sizes are untouched.
- The window is laid out as regions (`docs/ui-layout.md`): a browse panel on the left (folders, rescan, packs), the search bar and the preview above the result list in the center, an inspector with Parameters, Output and Info tabs on the right, the render queue with the drag handle and render cache in a bottom tray, and a status bar with the ffmpeg line and library counts. Panes resize with splitters (pointer or arrow keys) and collapse — the tray to a one-line summary that opens itself when the first render is queued — and sizes and collapsed state are remembered in `settings.json`. The favorite star and tag chips sit in a strip under the preview and in the Info tab, editing the same state. No feature was removed or changed in behavior.
- The library result list is now rendered by Preact from a shared state module (`src/core/app-state.ts`); keyed updates keep thumbnails alive while typing in search instead of rebuilding the list. No visible change otherwise. Decision record 0009 (superseding 0006) sets the approach for the coming UI work: Preact with signals, ported region by region behind the UI end-to-end test, today's parameter controls kept as they are; Preact is pinned to 10 after 11 missed the spike's bundle budget.

### Added

- Editing-app results recorded in `docs/nle-verification.md` from Premiere Pro 2026 and DaVinci Resolve Studio 20.2.3 on macOS: ProRes 4444 and PNG sequences import with correct alpha by default; QuickTime Animation needs Resolve's Data Levels set to Full; HEVC with alpha has no alpha in Premiere and needs Alpha Mode: Straight in Resolve; WebM cannot be imported in Premiere and decodes with broken alpha in Resolve; Premiere's linear compositing changes blended values by design. Drops into both apps' bins and timelines work from the queue and from Prepare for drag. Decision record 0008: straight alpha everywhere, no premultiplied option.
- Prepared renders are named after the template (`lower-third-bar.mov`, `lower-third-bar-2.mov`) instead of a hash, so clips in the editor carry a readable name; the cache keeps an index so an identical render is still found again. The app now says that editors link to prepared files and that clearing or evicting the cache takes those clips offline.
- Drag renders into your editor. A finished job in the queue can be dragged straight into an editing app's bin or timeline, and "Prepare for drag" renders the selected template with the current parameters, preset and options into a cache so the drag handle can carry it; an identical render is reused rather than redone. The cache folder can be changed, has a size limit (oldest files go first) and can be cleared.
- Template packs. Import a `.zip` or folder with a `pack.json` and one folder per template: a preview shows the pack's name, author and license, each template's id, license and size, and what will happen; licenses that are missing, non-open or unknown are flagged; a template whose id is already in your library folders is skipped, one installed from an earlier pack can be kept or replaced. Packs install into the app's user data, never into library folders, and join the library at once. Export the listed templates as a pack with a name, author and license. The format is in the template specification.
- Saved parameter presets per template: name the current values and save; apply from a list as an undoable step; saving over an existing name asks first. Only values that differ from the template's defaults are stored, in one file per template in the user data folder, and parameters a template no longer has are ignored.
- Batch rendering from CSV, in the inspector and as `--batch file.csv` headless: one render per row, columns matched to parameter ids or labels ignoring case, a `name` column naming the jobs and files, unknown columns listed as a warning before anything is queued, one folder asked for once.
- Your own tags and favorites on any library item, shown in the stage as chips (folder and manifest tags are listed too but cannot be removed) with a field to add more, and a star to favorite. Both are kept in the library database, survive folders going offline, and work in search: `tag:` finds your tags, `favorite:yes` lists favorites, `recent:10` lists the ten items most recently selected or rendered.
- Thumbnails in the library list: a poster frame for each template (rendered at mid-progress with default parameters) and a frame for each video and image (a tenth into the clip), made in the background, fitted into 240 px, cached in the user data folder and redone only when the item changes. Shown over a checkerboard so alpha is visible; audio shows a marker instead.
- Media metadata. Library media is probed with ffprobe in the background after each scan (duration, picture size, frame rate, codecs, alpha), shown in the list and details, cached by file size and time so only changed files are probed again. New search filters use it: `duration:>5` (also `<`, `>=`, `<=`, `=` and `5-10`), `width:`, `height:`, `fps:`, `res:1080p` (and `4k`, `uhd`, `8k`, `hd`, `fhd`), `codec:prores`, `alpha:yes`; templates answer the same filters from their manifests.
- Media preview. Selecting a video, image or audio file in the library shows it in the stage, with playback and seeking for video and audio. Files are served to the app window through a dedicated `pulp-media://<id>/` scheme that addresses items by library id, resolves the real file location and refuses anything outside the registered library folder (including symlinks that point elsewhere), serves only recognized media types, answers byte ranges, and returns a plain 404 for unknown ids, offline folders and missing files. Template pages cannot load from it.
- Persistent library index. Scanned items are kept in `library.sqlite` in the user data folder (`node:sqlite`, no native module; decision record 0007), so the app opens with its library at once and rescans only what changed: unchanged files and templates are kept without being read. Library folders are watched where the platform supports it, and the index is also refreshed when the window regains focus and when a folder that had gone missing is back. Items of a missing folder are shown as offline instead of being removed, so tags and favorites attached to them survive. Nothing is written into library folders. A synthetic library of 5,100 items scans in about 145 ms and rescans unchanged in about 105 ms.
- Decision record 0006: the UI stays plain DOM through milestone 3; the library milestone is the point to re-evaluate a component framework.
- Recent colors: each color field shows up to eight recently used colors, shared across templates and kept in `settings.json`; a committed color edit moves it to the front, and clicking a swatch applies it to that field.
- Parameter editing: number parameters with a range get a slider with direct entry; text parameters with a maximum length show a character counter. Undo and Redo (buttons, Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z or Ctrl+Y) record committed edits per template, with typing coalesced into one step; inside a text or number field the shortcut stays with the field's own undo. Each changed field shows a Reset, and Reset all clears the template; both are undoable. Edits and history are kept per template for the session.
- `docs/platform-notes.md`: the Electron, Chromium, ffmpeg, Windows and macOS findings behind the renderer (stale captures and the 60 Hz begin-frame cost, device scale, bitmap layout, ffmpeg 8.1+ alpha modes, color tags, Windows CI handling) with causes and fixes, so they are not re-solved.
- Color parameters have an alpha control. The native color input could only edit the RGB part and the alpha a template declared was kept but could not be seen or changed; each color field now has a slider for the alpha as a percentage, a text field for the whole `#RRGGBB` or `#RRGGBBAA` value, and a swatch over a checkerboard. A UI test drives the running app and reads the preview's pixels to confirm the alpha reaches the template.
- Render options, in the inspector and as headless flags: a frame-rate override (`--fps`) picked from the standard list (23.976, 24, 25, 29.97, 30, 47.952, 48, 50, 59.94, 60, 100, 119.88, 120) that samples the template at another rate over the same duration; the background color alpha templates are flattened over in presets without alpha (`--background #RRGGBB`); and in/out points (`--in-point`, `--out-point`), inclusive frames at the output rate entered as timecode `HH:MM:SS:FF` (three frame digits from 100 fps, semicolons for NTSC drop-frame), a frame number, or seconds such as `2.5s`. PNG sequences are numbered with the frame indices they hold. The inspector shows the resulting frames, rate and range, or the reason an entry is refused, and the queue validates before asking where to save. The preview's time display is timecode.
- `docs/nle-verification.md`: what is established about alpha (capture is premultiplied, every alpha preset is written straight), how a misread looks, a checklist for Premiere Pro, DaVinci Resolve and Final Cut Pro with a results table, and an alpha check test template (`tests/e2e/templates/alpha-check`) with an alpha ramp, 50% color patches, hairlines and moving text.
- Two output presets. "QuickTime Animation (alpha)": lossless RLE .mov with alpha for older workflows, full-range sRGB like PNG. "HEVC (alpha, macOS only)": .mov with an HEVC alpha layer through Apple VideoToolbox at quality 80 and alpha quality 0.9, tagged `hvc1` and Rec.709. Presets whose encoder the installed ffmpeg lacks are listed as unavailable with the reason, so HEVC shows why it cannot be used on Windows and Linux. Decision record 0005 explains why the HEVC encoder is fed 4:4:4 Y'CbCr rather than BGRA.
- Render queue: clicking Render asks where to save and queues the job, so several renders can be lined up and run one after another. Each job shows its own progress, result or error, and can be cancelled; finished jobs stay listed until cleared.
- Per-frame render timeout (10 seconds by default) and a 30-second load timeout, so a hung template stops the render with a clear message instead of hanging it.
- Headless mode flags `--library <folder>` (extra template folder for one run) and `--frame-timeout <seconds>`.
- End-to-end render test (`npm run test:e2e`, also part of `npm test`): renders the samples to ProRes 4444, VP9 WebM, PNG sequence and H.264 and checks frame count, size and alpha with ffprobe, plus the error and timeout paths. Skipped when Electron, ffmpeg or ffprobe is missing.
- Size verification at 4K (3840x2160), 8K (7680x4320) and portrait 1080x1920 for vertical video. Three size-probe fixture templates under `tests/e2e/templates` render as PNG sequences and the test reads pixels back to confirm dimensions, orientation and that the frame was captured at full size; 8K ProRes 4444 and portrait H.264 cover the video presets at those sizes.
- End-to-end check that frames stay pixel-exact with the display scaled to 150% (Chromium's `--force-device-scale-factor=1.5`), and a CI job on `windows-latest` that installs ffmpeg and runs the whole suite including the end-to-end tests. `PULP_E2E=1` makes the suite fail instead of skipping when a tool is missing. The job passes on Windows with ffmpeg 9.0.2, which verifies the renderer there: scale 1 capture, raw frames, Rec.709 output and the 150% scaling check.
- End-to-end check that a 2x offscreen surface (simulated with `PULP_OFFSCREEN_SCALE=2`) fails the render with the capture-size message instead of producing resized frames.

### Changed

- QuickTime Animation output carries a `colr` atom declaring full-range RGB (GBR matrix, BT.709 primaries and transfer); MOV has no range flag for RGB codecs, and without the atom Resolve's Data Levels Auto treated the file as video range and scaled the alpha. PNG sequences carry the same frame tags, which PNG ignores.
- Video presets (ProRes 4444, ProRes 422 HQ, H.264, VP9) now convert to Rec.709 with the BT.709 matrix at limited range and tag the output BT.709 primaries, transfer and matrix, limited range. Before, files carried no color information and ffmpeg used its BT.601 default, which shifted saturated colors in editors. Alpha templates are composited over the background in RGB before the conversion. PNG sequences stay full-range sRGB. Decision record 0004 has the reasoning, including why the transfer is tagged BT.709 rather than sRGB.
- Frames travel to ffmpeg as raw BGRA pixels instead of PNG images, removing a PNG encode in the app and a decode in ffmpeg per frame. Frames from alpha templates are unpremultiplied in ffmpeg, so semi-transparent edges keep their color. `--frame-format png` keeps the old path for comparison, and headless mode prints elapsed time and frames per second. Measurements are in `docs/system-design.md`; the reasoning is in decision record 0003.
- The offscreen render window is created at device scale factor 1 on purpose (Electron's `offscreen.deviceScaleFactor`), so templates see `devicePixelRatio` 1 and frames are captured at exactly the declared size on HiDPI displays. A capture at any other size now fails the render with a clear message instead of being silently resampled.
- When a template throws during a render, the error names the template, the frame, the error type and the file and line inside the template.
- The template bridge script is injected on one line so line numbers in template errors match the template's own file.

### Fixed

- The test suite can no longer stall on a child process. Every ffmpeg, ffprobe, Electron and build run the end-to-end tests start goes through one runner with no stdin, a time limit and a whole-tree kill (which Windows needs: killing Electron's main process leaves its helpers holding the pipes), ffmpeg is always started with `-nostdin`, the CI jobs have time limits, and on CI the reporter names each test as it starts, so a stall says where it is.
- The Info tab's Location row read `boardroom\lower-third` on Windows. It is a breadcrumb inside the library folder, not a path, so it now uses forward slashes on every platform; the tooltip keeps the native path.
- `settings.json` (library folders, recent colors) is written atomically: a temporary file is renamed over the old one, so a crash or a reader during a save sees the old or the new file and never a half-written one that would lose the library folder list. Changes that arrive close together are queued so none is lost.
- The end-to-end tests' cleanup no longer fails on Windows with EBUSY: they wait for the app to exit and delete scratch folders with retries, since Windows refuses to delete files a just-killed process still holds.
- The first captured frame could be blank or one frame stale on slow machines (seen on Windows CI with trimmed and flattened renders). The template bridge now resolves two animation frames after drawing, and the renderer forces a repaint and waits for the paint event before each capture, so the capture always holds the frame that was just drawn. The offscreen window's begin-frame rate is raised to 240 so the extra waits cost about 4 ms, which makes renders faster than before the fix (lower third: 67 frames/s raw against 54).
- Raw frames with ffmpeg 8.1 and later. Those versions negotiate an alpha mode on filter links and treat untagged raw input as straight alpha, so ffmpeg premultiplied the already premultiplied frames before the unpremultiply step: semi-transparent pixels came out dark (a white 85% panel read 216 instead of 255) and every color one step low. The renderer now detects alpha mode support and tags raw frames with their measured layout first. Verified with ffmpeg 8.0 and 9.0.2; found by the Windows CI job.
- Raw frames no longer depend on assumptions about the capture bitmap. The renderer measures the byte order and premultiplication of `toBitmap()` output with a probe page before the first render (Electron documents the layout as platform-dependent), passes the result to ffmpeg, and falls back to PNG frames with a warning if the bytes fit no known layout. The unpremultiply step is fed planar RGB explicitly so format negotiation cannot pick a lossy Y'CbCr intermediate.
- Cancelled or failed renders no longer leave partial output files behind. Files that existed before a render without overwrite are kept.
