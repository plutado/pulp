# Roadmap

Estimates are working hours for one developer, including tests and docs. They are rough; the total range reflects that. Checked items are done. The "still open" row is the sum of the unticked items' own estimates, not the previous figure minus what was finished — recompute it from the items, or it drifts.

"After 1.0" means not needed for the first release, not a place in the queue. Any such item is built whenever adjacent work makes it cheap — while the code it touches is open — and then moves into its milestone's 1.0 part; 1.0 is the line for what a release must have, never a gate on building.

## Where things stand

**Milestone 42, nothing empty takes room from the stage, is done:** an empty collection tray is not in the window at all and appears with the first item; empty results fold to their heading, which edge, the view controls are a quiet overlay on the stage's corner, and the window fits at every size: the page never scrolls, nothing overlaps, and the picture gets its share, held by a UI test at the default 1280 × 788. Milestone 37, the transport row, is done before it: the player's controls sit in one row across the bottom of the window, above the status bar, the scrub bar and the bars per layer at the window's width, and the stage is only the picture. Milestone 27, projects and the application menu, is done before it: a session saves as a `.pulp` project — guarded, recovered and relinked — and Pulp has its own menu on every platform. Milestone 28 is done before it — a layer has its own start, end, entrance, exit and look, with a bar per layer under the scrub bar — and milestone 30 before that — 85 of the 124 bundled templates declare how they stretch, and the other 39 move all the way through and keep their fixed length — and milestones 26 and 29 before that. Everything before it on the planned order is finished: the renderer and alpha export, the parameter editor, the library with search and categorization, drag-out, packs, the window shell and visual polish, browse and preview, collections, vertical and square formats, the sample library, image slots, layers, the browse panel's find field, and layers moved and resized on the stage. 358 bundled CC0 templates, a 626-file sample-media catalog, 66 types / 51 themes / 11 styles in the taxonomy, every type at least ten deep, every theme at least six with three assets of its own.

What is left for 1.0: signing and auto-update (7), which wait on account decisions. Stock library import (32) is done but for a look at real archives on the maintainer's machine; Lottie animations (35) are done; popping out the stage (43), still backgrounds to 32 and a still image output (44), effects (45) and objects (46) on transparency, unsigned builds (17), a deeper library (36), the transport row (37), the stage's right-click menu (39), one search in every chooser (40), search and browse in the left panel (41), nothing empty taking room from the stage (42), the start screen (31), the browse panel that says what things are (34, all but its card sort), layered graphics (33), converting library media (15), social-ready export (20), sound in a project (48), a cut track (49), captions from speech (50), keyframes on layers (51), clip clean-up for compositing (52), voice treatments (53) and 1.0 hardening and docs (8) are done. Four verification items wait on hardware: two need the test Mac, and two on Windows are checked in a Windows 11 virtual machine. Known issues and ideas not yet decided are in `docs/ideas.md`.

Milestones keep the number they were given when they were added. Milestones 1 to 23 have GitHub issues of the same number; from 24 on, a new milestone's issue number is given beside its heading, since pull requests share GitHub's numbering. A decision is written here as soon as it is made — a new milestone, or items in an existing one — even when it is low priority and may never be built, so everything decided is visible in one place; `docs/ideas.md` keeps only ideas not yet decided and known issues. The table and the sections below are in **planned order**, which is not numeric order. Packaging and signing (17 and 7) come last, after hardening: packaging is the final step, and what it wraps should be the finished thing. The window layout that the UI milestones build, and why they come in this order, is in `docs/ui-layout.md`.

## 1. Headless frame renderer, production quality (12-20 h)

A first renderer works (offscreen window, PNG frames to ffmpeg). This milestone makes it dependable.

- [x] Automated end-to-end render test that runs when Electron and ffmpeg are available, checking frame count, size and alpha with ffprobe (2-3 h)
- [x] HiDPI: render at device scale 1 explicitly instead of resizing captured frames; verified on a Retina display (2-3 h)
- [x] HiDPI: verify on Windows at 150% scaling. Verified by simulated 150% scaling on Windows CI: the e2e suite renders with Chromium's `--force-device-scale-factor=1.5` (the primary display reports 1.5, as Windows does at 150%) and checks the frames stay pixel-exact; the `windows-latest` job runs the whole suite with `PULP_E2E=1` and passed on ffmpeg 9.0.2 (1 h)
- [x] Large frames: verify 4K and 8K, and portrait sizes for vertical video (1-2 h)
- [x] Throughput: avoid PNG encode/decode by piping raw BGRA (`-f rawvideo -pixel_format bgra`) from `capturePage()`, with `unpremultiply` for alpha templates (ADR 0003 explains why not the `paint` event); benchmarked against the PNG path in `docs/system-design.md` (3-5 h)
- [x] Color: decide and document sRGB/Rec.709 handling: video presets convert with the BT.709 matrix to limited range and tag every frame BT.709 (`scale` + `setparams`), PNG stays sRGB; ADR 0004 (2-3 h)
- [x] Robustness: per-frame timeout for hung templates, delete partial output on cancel or failure, clear errors when a template throws (1-2 h)
- [x] Render queue: several renders in sequence with progress per job (1-2 h)

## 2. Alpha export presets and NLE verification (8-14 h)

- [x] Verify each alpha preset imports with correct transparency in Premiere Pro and DaVinci Resolve on macOS; results in `docs/nle-verification.md`. ProRes 4444 and PNG pass with defaults; QuickTime Animation needs Data Levels: Full in Resolve (now tagged full-range RGB, re-check); HEVC: no alpha in Premiere, Alpha Mode: Straight in Resolve; WebM: not importable in Premiere, broken alpha in Resolve (3-5 h)
- [ ] On the test Mac: re-check whether Resolve's Data Levels Auto honors the new full-range QuickTime Animation tag (1-2 h)
- [ ] Verify alpha import in Premiere Pro and Resolve on Windows, in a Windows 11 virtual machine on the maintainer's Mac (also used for debugging Windows-only failures); if either app can't run in the VM, the check waits for a real Windows machine and stops blocking 1.0 (1 h)
- [x] Straight versus premultiplied alpha: Chromium captures premultiplied (measured by a probe), every preset is written straight, Premiere and Resolve read ProRes, PNG and Animation as straight; no export option, HEVC's Resolve default documented as a caveat; ADR 0008 (2-3 h)
- [x] Additional presets: QuickTime Animation (qtrle) for older workflows, HEVC with alpha on macOS via VideoToolbox where available; shown as unavailable elsewhere with the reason; ADR 0005 (2-3 h)
- [x] Preset options: frame-rate override from the standard list, background color picker for flattening, in/out points as timecode or frames; in the inspector and as `--fps`, `--background`, `--in-point`, `--out-point`; verified on macOS and Windows CI (1-3 h)

## 10. Categorization by type and theme (14-23 h)

After milestone 11 (the browse panel it fills) and before milestone 8: it changes the template manifest and `pack.json`, additively, so templates written before it keep working. Housekeeping for the first commit: fold `main.ts`'s remaining `state.index` into the shared state, so the index lives in one place before the tree builds on it.

- [x] Taxonomy: built-in, versioned lists of types (nine groups over 45 types), themes (eight groups over 50, user-extendable: any tag-normalized word is a custom theme, shown in a separate group) and styles (eleven, closed) in a pure core module (`src/core/taxonomy.ts`) with membership, normalization and category mapping helpers, unit tested; ADR 0010 records the three axes, what is open and closed, and the ids-are-permanent extension rule (2-4 h)
- [x] Template format: optional `type` checked against the list, `themes` (normalized; unknown ids are custom, not errors) and `styles` (built-in only, errors otherwise); `category` stays valid and maps onto the type list, so existing templates keep working; validator with tests, `docs/template-format.md` and changelog updated (2-3 h)
- [x] Media files: type inferred from the media kind plus folder names (`sfx/whoosh/…` → whoosh; type ids, labels and plurals all match; no folder means no type rather than a guess), built-in themes collected along the path (`Sports/Hockey/…`); user themes — built-in or custom — editable in the Info tab next to the tags, stored in `user_items` like tags (schema migration keeps existing user data) and surviving offline roots; the Info details line names the type (2-3 h)
- [x] Search: `type:` takes a taxonomy type or a type group as well as the media kinds (several `type:` terms are alternatives), `theme:` matches manifest, folder and custom themes (all terms required), `style:` matches a template's declared styles; all combine with the existing filters, free text finds types and themes by id, and the filters are listed in the search field's hint. The filter chips stay as decided — media kinds, alpha, favorites — so the chips and the taxonomy never offer competing "type" vocabularies (1-2 h)
- [x] Browse tree in the browse panel (`src/core/browse-tree.ts`, pure and tested), replacing milestone 11's flat node list: Quick access (Favorites, Recently used), Types (group → type, with an Untyped node for templates of category "other" and media no folder typed), Themes (built-in groups plus a Custom group), Styles and Folders ("Built-in templates" first), each node with a count. Counts follow the typed query and the chips but not the scope, so selecting a node never zeroes the others; empty taxonomy nodes are hidden rather than dimmed (the tree maps what the library has), while the fixed places — Favorites, Recently used, Untyped, folders — are always shown and dim at zero. Type-group icons from the style guide's map, humanized labels, full folder path in the tooltip; headings fold; Up/Down/Home/End move, Left folds or steps out to the parent and Right unfolds or steps in, Enter selects. The three levels are told apart by structure, not type size (`docs/ui-style.md`): sections are headings over a rule and are not rows, rows that hold children get a twisty in a fixed gutter before their icon, and children indent behind a guide line without repeating the icon. Selecting a node sets the scope chip and narrows the results, clearing widens; the end-to-end test selects a type node and checks the chip, the results and the count. ## 19. Vertical and square formats (13-21 h)

Before milestone 8, which writes the authoring guide and the JSON Schema: both should describe the format as it ends up, not one that is about to change underneath them.

**A template is defined by its aspect ratio, not by a pixel size.** A lower third is a lower third at 1920 × 1080 and at 1080 × 1920; what differs is the shape of the canvas and where things sit in it. Today's manifest declares `width` and `height`, which pins every template to one resolution and makes a vertical version a second template to write and maintain. This milestone moves the pixel size to render time and leaves the template saying only which shapes it is drawn for.

- [x] Template format: a template declares the aspect ratios it supports (`aspects`: 16:9, 9:16, 1:1, 4:5) instead of a pixel size, and draws relative to the canvas it is handed; the frame state's `width` and `height` are now the render's, passed in by the caller rather than read off the manifest. The output resolution is chosen at render time through a pure `src/core/aspect.ts` (standard sizes per aspect, 720p to 4K and 8K for 16:9; an exact size; the checks that a size is of its aspect), carried in the render options as `aspect`, `width` and `height` and as the headless `--aspect` and `--size` flags. Manifests with `width` and `height` keep working: the aspect is inferred (a built-in one within 1%, else the reduced ratio such as 4:3, at which the template renders at that one size) and the size becomes the default resolution. The renderer sizes its offscreen window from the plan's size rather than the manifest, the capture-size check and ffmpeg's input follow it, and thumbnails, hover-scrub strips and the preview take the template's default size. The library re-reads templates once (schema 5) so stored manifests carry their aspects. ## 23. Layers in templates (37-56 h)

After milestone 22, which it grows out of, and before milestone 8's schema and authoring guide, for the same reason every format milestone comes first: the guide should describe the format as it ends up.

Milestone 22 gave a template fixed image slots: the author decides where a logo goes and it rides the animation. This milestone lets the **person using the template add a layer the author did not put there** — another line of text, a second logo — and have it ride the animation just the same. A template declares **blocks**, a box per aspect where layers may live; layers stack inside a block and take their part of the template's movement from their position in the stack, so an added line enters, moves and leaves with the design rather than sitting on top of it. The author stays in charge of the look: a layer is drawn with the block's typography and the template's motion unless it is deliberately overridden.

Milestone 22's fixed image slots stay exactly as they are. A slot is the author's; a layer is the user's.

- [x] Template format: `blocks` and `layers`. A block is a box per aspect (fractions of the frame, like an image slot), a stacking direction and spacing, the typography its text layers start from, and whether it is full or may take more. A template's own layers are its defaults, each with a type (`text` or `image`), its properties, and optional `required` so it cannot be removed. The stack position is what the template animates by, so a layer added in the middle takes the movement of the position it is in. Validator with tests, `docs/template-format.md`, an entry in `CHANGELOG.md` (4-6 h)
- [x] Blocks draw. `state.blocks` carries each block for the frame — its box in pixels and the layers that are drawn, in stack order — and the bridge finishes the job: `pulpLayoutBlock` measures, wraps, shrinks or truncates, stacks and places, and `pulpDrawBlock` draws the result, with a per-layer hook called by stack position so an added line takes the movement of the position it is in. The arithmetic is a pure module with unit tests and the bridge mirrors it (4-6 h)
